# 兔子镜 1.62：串行多面与按正文挑签

两个功能都是实验项，默认关闭。关闭时，多面仍是一次请求出全部面，抽签仍是本地纯随机。

## 串行多面（仅副 API）

多面设置里二选一：

- **一次请求出全部面**：现在的行为。本地先抽完所有面，一次请求写出 N 个平级 `<toto>`。
- **逐面排队**：仍然先一次抽完 N 面，然后按顺序一面发一次副 API。不并行。跟随正文的那一次生成不走这条队列。

要 3 面就发 3 次。某一面失败就跳过，继续后面的面，已经成功的面留下。队列走完若少于要求的面数，再看现有的「自动重 roll」：

- 开着：缺的面用原来的签再请求，整批共用现在的重 roll 次数。成功就补回原来的位置。次数用尽仍失败，那一格显示生成失败。
- 关着：不补发，那一格直接显示生成失败。

重试不重抽。额度不足、点停止、切聊天，沿用现有规则，不继续重试。每一面使用完整的最大输出，不再和同批其他面挤同一次补全。

## 按正文挑签

抽签方式二选一：

- **本地纯随机**：现在的加权抽签。
- **按正文挑签**：仍只有写作那一次 API。范围判断和写小剧场在同一次请求里完成。

百分比在设置里调，默认贴正文 70%、平行 30%，每一面单独掷。平行就是主题带 `if` 标签的线（ABO、哨向、世界观变更等都在这组）。库里没有的题材不会被凭空抽出来。

发出请求之前：

1. 冷却、黑名单、收藏权重走现有过滤。
2. 贴正文的一面，从非 `if` 主题里按现有权重抽出大约 12 个主题、12 个展现形式，再抽 3 到 4 张完整的签。同一张菜单里，主题和展现形式都不重复。近几轮已经用过的主题、展现形式会先排除；池子不够时才退回软权重，避免抽不出签。
3. 平行的一面不进菜单，直接在 `if` 主题里本地抽一张签并锁死。这样模型不会挑一条最接近当前情节的「平行」。
4. 本批后面的面避开前面各张菜单里已经占住的主题和展现形式。

写作请求列出这几张签。模型按最新正文氛围选一张，先写 `<rm-ticket>序号</rm-ticket>`，再只按那张签写小剧场。回复里的序号用来记冷却：只冷却被选中的那一张，菜单里没选中的不进正式历史。序号不在菜单里时，这一面按生成失败处理，交给现有重 roll。

用户点菜、世界书单条抽签、纯文本条目抽签不走这张菜单。

## 和旧行为的边界

- 跟随模式可以用按正文挑签。串行排队只在副 API。
- 自动重 roll 的开关、次数、不重试的情况都不变，串行只是按面消耗这些次数。
- 不新增第二套冷却。交互家族和配色冷却仍留在写作提示词里。
