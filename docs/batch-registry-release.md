# 任务登记释放修复：1.6.16-test.1

基线：测试分支 `48424d8`，与正式分支 `c4d27a6` 的运行文件一致，版本 1.6.15。

## 原因与修复

独立 API 重试曾直接覆盖 `flight.batchPlan`，只在整个生成任务结束后释放最后一次计划。多面失败后重试单面时新计划为 null，首轮登记留在本地；重复操作可达到登记上限 8 项。取消流程同时清除了超时器，若宿主忽略取消信号，原 Promise.race 无法结束，也到不了 finally。

功能修改限 `src/independentApi/mount.js`：

- 按精确 batchId 和 identity 保留本任务的登记引用，不保留额外正文副本。
- 每轮的 finally 在成功提交之后、下一轮请求之前释放该轮登记；最终清理再次尝试尚未释放的记录。
- 取消拒绝本地等待，独立于宿主是否响应取消。不能保证上游服务实际停止或退费。
- 每轮捕获自己的控制器和标记；迟到计划、抽取诊断和进度回调不能改动下一轮状态。
- 其余运行文件只同步缓存标识，保持模块引用一致；生成规则、输出、抽签、请求参数和重试次数均不改。

## 验证

使用 Node 内置测试和真实存储模块、真实轮次调度代码及补缺合并函数，宿主网络和 DOM 为隔离边界，不调用付费模型。

- 新增回归首次运行：6 项中 4 项失败，确认登记残留、容量耗尽、取消悬挂和迟到回调问题；原有成功提交、绝对超时路径通过。
- 修复后新增 9 项通过，包括保留成功面后补单面、跨过 8 次的连续重试、取消、超时、迟到回调及释放写入失败后再试。所有清理用例保留另一任务的登记和无关内容。
- 相关组：51 项，50 通过，1 项因缺少外部历史 ZIP 基线跳过，0 失败。
- 完整套件：最终候选 365 项，330 通过、28 失败、7 跳过；1.6.15 原基线 356 项，321 通过、28 失败、7 跳过。失败名称逐项比对完全一致，没有新增失败；不是全套通过。原失败主要来自既有测试夹具、源代码抽取和旧断言，与本修复分开报告。

## 历史登记与验收边界

没有放宽登记容量，也没有清空登记表。旧记录没有足够的存活证据，不能根据当前页面没有请求就判断另一页面或跟随模式的登记无效。旧版遗留未满 12 小时的记录可能仍然阻止新请求；超过原有期限后，下次登记按原规则回收。刷新不承诺立即恢复。

未在用户实际酒馆、手机或真实模型连接中复现与验收。测试通过证明已覆盖的任务生命周期行为，不代表全部宿主兼容性通过。
