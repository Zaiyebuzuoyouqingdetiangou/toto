# 任务登记释放修复：1.6.16-test.2

基线：test.1 提交 `3ce1cdb`；原始测试基线 `48424d8` 与正式分支 `c4d27a6` 的运行文件一致，版本 1.6.15。

## 原因与修复

`BATCH_REGISTRY_CAPACITY` 是临时任务登记达到 8 项，不是 API 额度不足，也不是浏览器存储字节不足。独立 API 重试曾覆盖 `flight.batchPlan`，结束时只释放最后一次计划；取消时若宿主忽略信号，旧等待也可能无法结束。test.1 已修复每轮释放、取消结算与迟到回调，但旧版本留下的未满 12 小时登记仍会阻止生成。

test.2 将独立 API 的临时计划放在当前页面的存储模块内存中。它们没有跨刷新恢复请求的用途；页面结束后自然释放，无须推断其他页面的任务是否死亡。独立路径在读取旧共享表之前分流，因此旧表满额或损坏都不会占用新请求的登记位置。旧表不迁移、不强制删除，跟随正文仍使用原路径。

- `src/storage.js`：增加独立临时登记；查找返回副本，提交与释放必须精确匹配 batchId 和 identity。登记前先持久保存抽签尝试与公平性记账，写入失败不建立内存登记；成功历史落盘之后才移除登记。
- `src/independentApi/request.js`：在原发送租约边界显式选择临时登记。只有独立 final-body 身份可以使用，跟随正文和预览不能借此改变原有行为。
- test.1 的 `src/independentApi/mount.js` 生命周期修复继续生效：每轮释放、宿主忽略取消时仍结束本地等待、旧轮回调不可更改新轮状态。
- 其余运行改动仅同步缓存标识，保证模块引用到同一份 storage。版本为 1.6.16-test.2。

原有 8 项活动登记及单计划大小保护保留；当前独立路径只计算当前页面的活动登记，不计其他页面或旧版持久表。未新增限额、重试次数或网络请求；抽取、Prompt、请求参数和已保存成品不变。

## 验证

使用 Node 内置测试，真实存储模块、真实轮次调度代码、补缺合并函数和实际请求函数；宿主网络及 DOM 为隔离边界，不调用付费模型。

- 新存储回归在未修改生产代码时：9 项中 6 项失败，确认旧表满额、损坏、刷新残留、页面共享占位等缺口；修复后 9 项全部通过。
- 新增实际多面请求入口回归：旧共享表已满 8 项时，仍到达模拟发送边界一次，旧记录保持原样。
- 生命周期 9 项切换到新登记路径后全部通过，包括超过 8 次连续重试、保留成功面再补单面、取消、超时、迟到回调和清理失败再试。断言同时检查当前内存登记已释放及其他任务、无关内容未变。
- 上述测试加请求前置检查共 24 项全部通过；覆盖写入失败回滚、失败提交保留登记、部分提交、身份不匹配、两页面隔离与刷新后不恢复临时登记。
- 完整套件：375 项，340 通过、28 失败、7 跳过；1.6.15 原基线 356 项，321 通过、28 失败、7 跳过。失败名称逐项比对一致，没有新增失败，不能称为全套通过。既有失败主要涉及测试夹具、代码抽取和旧断言。

## 验收边界

这是对独立 API 旧登记残留阻塞的机制修复。真正的浏览器存储不足、网络错误、模型空回或格式不完整仍可能失败；它不替代原有空间清理，也不保证所有“独立 API 失败”都被解决。多个页面的持久记账仍沿用原 localStorage 事务，不声称获得跨页面数据库锁。

更新后必须完整刷新或重启宿主以加载新模块，不用清站点数据、删除成品或重新导入母本。取消仅结束本地等待，不保证上游已经停止或退费。尚未在用户实际酒馆、手机或真实模型连接中完成验收。
