万行整文件已经拆完。`outputSanitizer.js`、`independentApi.js` 是桶文件；`ui.js` 留下 mount / destroy / 事件绑定。延迟入口仍指向这三条旧路径，不必改启动图。

## 两类维护痛

| 类型 | 现状 | 做法 |
| --- | --- | --- |
| 文件太长 | 第一刀按家族切开后，仍有一批 1500～4300 行 | 只在家族内部再找真实边界，不要按「每 200 行切一刀」 |
| 单行太长 | `CHANGELOG.md`、`appearanceReference.js`、`settingsAppearance.js` | 换行；不改语义。不要和拆文件混在同一轮 |

## 不要拆

- `data/structured/*.js`：构建器生成，改 raw + 跑 `library:write`
- `data/raw/*` 里「一条母本必须同一行」：见 `docs/library-index-builder.md`
- 历史 `docs/update-1.5.*.md`、验证记录
- 互相调用的同一条 rescue / 生成链路：拆成几十个 80 行文件会更难跟
- `injector.js`（1043）：在解析关键路径上，拆错会拖主回复
- 已经够短的桶文件、`runtime.js` 叶子、`ui/settingsTemplate.js`（纯 HTML）

## 硬约束

1. **缓存戳**：新文件 import 必须带 `?rmv=`；拆出后旧文件和新文件的戳一起升。
2. **旧路径兼容**：`outputSanitizer.js`、`independentApi.js` 继续做桶；`ui.js` 继续做入口。不要一次改完所有 import。
3. **禁止新环**：sanitizer 不要 import independentApi；几何/挂载不要 import 整份 sanitizer，只拿已经在用的那几个函数。
4. **测试**：抽出后补该领域的小测试，不要默认加载整份 sanitizer / independentApi。
5. **行为不变**：rescue 触发条件、存储 key、DOM 属性名、失败卡/五版 swipe 语义一律不借拆分改掉。
6. **一次一块**：一个 PR 只搬一个文件夹或一条清晰边界。搬完跑 `tests/` + 受影响语法检查。真要合入时再升产品版本。

## 推荐批次

1. **还没按目录拆过的 ≥1500**：`visualScanner.js` 或 `storage.js`（边界比再切 rescue 家族清楚）
2. **`independentApi/geometry.js` 或 `connection.js`**：几何已有固定布局桩测试；连接主要给设置页用
3. **`outputSanitizer/markup.js` 或 `maintenanceInspect.js`**：字符串净化 vs 维修巡查，和 DOM rescue 族耦合较少
4. **`ui.js` 剩余绑定**：只在某一整块设置（连接 / 高级弹层）真正难跳时再拆
5. 最后才考虑把桶文件改成 `outputSanitizer/index.js` 并改 `index.js` 的延迟 import

每批完成标准：

- 调用方 import 路径可暂不改（桶文件或 `ui.js` 顶上）
- `tests/` 全绿；新模块有至少一条能脱离整文件跑的测试
- 手动点一次：生成、重说五版、失败卡不占格、维修恢复到初始、标题星标、设置开关
- 版本号与 `?rmv=` 同步（真要合入时再升，不在拆到一半升）

拆分轮次不要夹带：新 rescue、改自动重 roll 默认、改 5 版上限、改收藏存储、改 Prompt。那些走普通功能 PR。
