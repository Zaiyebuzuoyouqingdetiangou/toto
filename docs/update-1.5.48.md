# 1.5.48 外部母本修复测试

本版基于保留的 1.5.47，修改的是实际抽取和材料发送，不新增诊断入口。

## 修复内容

1. 先前某次点菜缓存了内置随机形式，后来启用外部库，新的一轮仍沿用内置结果。现在可用条目的变化会使这类旧缓存失效；只重新计算新操作的随机半边，明确点菜和正在执行的请求不变。
2. 自动摘要先拼标题、关键词，可能把正文挤出精简模式的发送范围。新导入摘要改为正文优先；已保存旧库仅对选中且精确匹配旧生成结果的摘要修正发送副本，无须重导，不写回数据库或存档。

标题、关键词、母本原文、人工修改后不同于旧算法的摘要仍保留。无法区分“完全同字节的手工摘要”和旧自动摘要；超过有界扫描且无法确证的旧条目不修改。没有增大原摘要/原文预算。

## 保留边界

- 不提高外部抽取比例，不改变内置优先/均衡/外部优先等选择；动态视觉固定内置形式、明确点菜和可用池不足时的既有规则继续保留。
- 不新增常驻轮询、Observer、整库原文读取或额外请求；库指纹在原有轻量 ID 快照构建中计算。
- 不因模型效果普通拒收作品；失败不自动重发。
- 多页面同时改库后，另一页面的旧内存快照仍可能需要刷新；本版没有新增跨页面同步机制。建议在当前生成页面管理库，另一页面改动后先刷新。
- 不是 TT 虚化内嵌修复：此前的独立查看面板保留，late-projection 仍需另行适配。

## 验证与安装

针对性故障测试 45/45；原版的 UI/IndexedDB 启用→新生成复现失败，本版通过，且同一操作不重新抽取。全套旧测试仍有 45 个与 1.5.47 相同的失败，不表述为全绿。JS/ESM 与压缩包检查见开发目录的验证记录。

仅源码/自动化验证，尚未真机验证；没有真实 Gemini/DeepSeek 付费请求，不能认定这些缺陷就是反馈的唯一原因。

更新当前 tt-test 分支或原安装目录，覆盖 ZIP 内 RabbitMirror 文件夹里面的文件与子目录，重启 TT 确认 1.5.48。不要清空站点数据、重新导入库或同时启用两份插件。未替用户上传 GitHub。
