# 1.5.49 TT 立即启动测试

这是 tt-test 专用安装包，不替换 main 的 1.5.48 正式包。不是“保证不错过 TT 登记”的修复版。

## 本次实际改变

- 入口执行时同步尝试登记，之前没有静态模块请求和顶层等待。注册桥与主体共用同一实例。
- TT 的核心在 DOM 就绪后立即开始加载，不再等待 idle、聊天稳定三秒或已挂载租约；修正注册被拒后正常设置也无限等待的问题。网络下载和 DOM 就绪本身仍需时间。
- 移除备用设置栏、截图中的两个按钮和独立查看面板，使用原来的完整设置与正文显示路径，不提供另一种剧场显示方式。
- 非 TT 保留原延迟机制；不改母本选取、按需读取、Prompt、维修、交互、历史成品、自动生成设置或单次付费请求限制。不会因为升级自动重发失败请求。

## 尚未解决的边界

如果 TT 在开始执行插件之前就已经冻结 ChatSurface 参与者名单，入口仍返回 `managed=true / registered=false / late-projection`。取消插件自身等待只能让正常设置启动，不能重新登记或收到虚化消息的挂载回调。此时正文兔子镜仍不可用，不能将设置恢复视作内嵌恢复。

本版不伪装 system 扩展，不修改 TT 的宿主代码，不关闭 DOM 虚化，不把未注册的 managed TT 当作普通宿主硬改聊天节点，不新增常驻轮询或登记重试。

立即启动会提前解析与初始化核心模块；原有成品记录检查也会提前执行，并不是零历史读取。外部母本仍按需读取。真实 TT/iPhone 的启动耗时、温升与滚动流畅度尚未验证。

## 安装与回退

1. 备份原扩展文件；不要删除聊天、库或站点数据。
2. 在 GitHub 选择 `tt-test`，上传 ZIP 解压后 `RabbitMirror` 里面的文件与子目录，根目录应直接包含 `manifest.json`、`tt-entry.js`、`index.js` 和 `src`。不要上传 ZIP 文件本身，不要覆盖 main。
3. 已安装 TT 应从原扩展目录更新；不要并存启用两份兔子镜。完整退出并重启 TT，再确认版本 1.5.49。
4. 本版不加载旧 `src/ttSettingsEntry.js`、`src/ttTheaterViewer.js`。如果覆盖时旧文件遗留，无须为此清空目录。
5. 回退时覆盖回保存的旧版本文件并完整重启；不要借回退重建或清除成品和母本。

不用重新生成来测试。先查看正常设置是否出现并能展开，再查看已有正文镜面。若诊断仍是 `late-projection`，本版没有修复该主故障，不必反复点击设置或消耗 API 重试。

仅源码/自动化验证，尚未真机验证。验证报告随交付保留在开发目录；安装包不包含 tests、scripts 或 package.json。
