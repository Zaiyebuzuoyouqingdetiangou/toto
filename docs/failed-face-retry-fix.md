## 用户可见行为

- 失败的一面即使丢失逐面抽取记录，也可以直接点「重说」。会提示按当前勾选设置重新抽取这一面，其他面保持原样。
- 原记录完整且条目仍可用时，沿用原选题。失败面的原条目已停用或无法还原时，提示后只为这一面选取当前可用条目。成功面仍保持原选题契约。
- 一面重说按一面判断完成，不再拿整批面数判断单面响应。补生成的一面能正确合并回原位置。
- 成功后保留其他面的抽取记录；旧批次仍有失败槽时继续显示未完成，不误报整批完成。
- 发送前固定实际选题。已启用的自动补生成沿用本次选题；没有可信记录时不会携带手动重新抽取授权再次随机请求。

## 原因与边界

挂载页面恢复出的 HTML 副本不含 `apiRequest`，旧逻辑优先采用该副本，导致重说后丢失逐面记录。另有单面响应误用整批面数、单面补生成误用严格多面解析、失败结算覆盖完整诊断的问题。此次分别修复记录携带、响应计数、单帧合并及诊断保留。

不放开已停用条目，不替换其他成功面的内容，不添加整段聊天保存、轮询或自动整批重说。新抽取仍受当前候选与来源校验约束；完全没有可用条目时仍会明确报错。
