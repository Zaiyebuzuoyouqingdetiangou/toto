# 兔子镜小剧场

新增了更新日志板块，感谢 @nancyindaeyo 的更新。

## 1.73.20 建档角色写成「long black hair」这种时，插件认不出是发色

- 柏宝绘自动建档的标签常写成「long black hair」「big red eyes」，长短、样子和颜色连在一起。插件以前只认「black hair」「red eyes」这种两个词的写法，所以这类建档虽然读到了，却没被当成发色、瞳色：模型写的「黑发」「black hair」没被去掉，和建档的银发一起发给生图，就画成了另一个样子。现在先把长短、样子的词去掉再认颜色，这类建档照样压过模型写的；发饰（hair ornament）、眼型（narrow eyes）这些不算颜色，不会被误删。

## 1.73.19 生图长相来源定一个顺序：建档角色 → 角色卡／Persona → 世界书 → 模型写的

- 以前几条路上长相的先后不一样（生图 LLM 那条把世界书排在了角色卡前面；出图前补长相只查建档和世界书，角色卡没查），加上 1.73.13 起画面描述里也写长相，建档写银发、画面里写黑发，两种一起发给生图就画串了，「文生图是一个样子、小剧场是另一个样子」就是这个原因。现在三处（写兔子镜、生图 LLM 规划、出图前补长相）都按同一个顺序：柏宝绘／智绘姬里建档的角色 → 角色卡和 Persona → 这张卡绑定的世界书 → 这一面模型写的；前面有的，后面写得不一样的发色、瞳色一律去掉，衣着、动作照留。单人卡的长相写在角色卡里，现在也补得上。
- 画面描述里不再写发色瞳色（1.73.13 的那条改回来），长相只写在逐人那一条里，由上面的顺序决定内容。
- 没开生图 LLM 时，生图面板里每张图多一行「长相来源」：阿岩=建档、阿雪=人设、某某=世界书、某某=模型写的。画得不像时看这一行就知道是没对上建档（名字写得不一样）还是哪一步没读到。角色卡里的 {{char}}、{{user}} 会先换成名字再找；长相写在几百字背景后面的角色卡也找得到；群聊没有当前角色卡，只读 Persona。

## 1.73.18 画面说明少被审核截断；不多花副 API

- 撤回测试版 1.73.17 里「模型没写画面的图框让副 API 另写一份」：不多调副 API，图框照样留着。
- 画面说明写在每一面最后，最容易被服务商的内容审核截掉（截在这里这张图就没有画面，插件只能拿标题和旁边的字凑一段）。现在要求模型写画面说明时不用露骨的字眼（性器官、性行为的直白说法、裸露部位），用含蓄的写法写姿势、距离和神情、写清衣着；亲密、暧昧的情节照样可以画。不多调副 API，图框照样留着。
- 拿标题和旁边的字凑提示词时，标题以前会把标题条上插件自己的按钮（小兔子、收藏星这些）的字也算进去，现在发给生图的那段只取标题字。存图的位置仍按以前的算法，已经画好的图不会因此重画。

## 1.73.16 外置兔子镜挂上去以后自己检查有没有被美化挡住

- 有的美化在正文里铺了好几张大装饰图（山水、古琴之类），兔子镜挂进正文后被盖住；有的美化把正文挤偏，兔子镜跟着超出画面。插件拿不到美化的文件，也不猜它怎么写，现在挂好以后自己看结果：兔子镜滑进屏幕时，在标题条上取几个点，看点到的是不是这条消息里别的东西（装饰图写了点不到的也照样量得到）。被盖住了先把兔子镜往上提一层；还盖着，或者整块左右超出了这条消息的边，就往外挪一层（正文里 → 正文下面 → 整条消息外面）。挪过以后这一面就一直按挪过的那层放。
- 只有「自动」挂法会挪；手动选了「进正文」「整条消息外面」的只往上提、不挪。跟随正文的外置兔子镜也会往上提。等位置稳下来（Swipe 的滑动动画走完）才量；一面最多动四次，不会和美化互相推。换了一版（Swipe、重说）、改了挂法设置，上一版量出来的结论不作数，重新量；还在生成、正文还在流式输出时不量。酒馆自己的翻页箭头、消息按钮、头像不算挡住。

## 1.73.15 模型漏写或写错长相时，插件从世界书补

- 光在提示词里要求「每个人都写长相」不够：模型还是会把某个人的外貌那一条写成空的，或者照常写成「黑发」、和世界书里的设定对不上。现在出图前插件自己按图框里的人名，去这张卡绑定的世界书里摘出这个人写长相的那几句（多人条目里只摘到这个人那一段为止），放在最前面；世界书写了发色，就去掉模型写的发色那几个字，写了瞳色就去掉瞳色那几个字（发带、闭着眼这类不动，衣着、动作照留），英文标签里「颜色＋hair／eyes」的也一样去掉（带权重括号的整串不动）。认得的写法：黑发、乌黑长发、黑色的头发、一头银发、发色偏深；碧眼、蓝色的眼睛、深色瞳孔、眼睛是蓝色的；发带、发夹、眼镜、白发苍苍不算。写空了的那个人也会补回来，以前写空的人整个不发给生图。「阿岩的妹妹」「阿岩岩」这种不算阿岩；同一段里写了几个人时，只摘到下一个人为止。角色库里配了这个人外貌的，以角色库为准，不从世界书补。出场人物相同的几张图在一分钟内共用一次世界书读取。NAI 4.5 标签写法只收英文标签，用不上中文原文，这一步不做。
- 开了生图 LLM 时：发色、发型、瞳色这些不会因这一幕改变的长相，以角色库和世界书为准，这一面写得不一样的不用；当时衣着仍以这一面写的为准。

## 1.73.14 外置兔子镜的正文和标题一样宽

- 模型常把正文那一块写成在整面外框里缩进一圈（左右各留十几像素），外框是整面自己画的。外置时整面外框被清掉、换成单独的标题条，正文就比标题条左右各窄一截，手机上特别明显。现在这种左右对称、不超过 40px 的缩进会去掉（上下不动），正文和标题条一样宽；写死宽度、靠居中摆着的卡片，和窄面在宽屏上居中那种（左右留得很宽）不动。跟随正文的外置兔子镜也一样处理（单面、多面、恢复出来的都算），模型写的整面外框也会挪到正文上（以前只有副 API 的会挪）。收起着的面展开时再量，多面切到哪一面量哪一面。这些记号不进存档和收藏。

## 1.73.13 生图 LLM 和手动生图也读得到世界书里的人物长相

- 画面描述（自然语言写法）写到每个人时，把最显眼的长相紧跟在这个人后面写，比如「黑色高马尾的青年」「绿色眼睛、左耳戴耳钉的少女」，不并成一串，生图分得清谁是谁；完整长相仍然逐人写在逐人外貌那一条里。1.73.12 让画面里一律不写长相，改回来了。NAI 4.5 标签写法的画面里仍然不写长相标签（标签分不清是谁的），只写在逐人那一条。
- 开了生图 LLM 的内置生图，和小兔子里的手动生图，用的是同一个画面规划。以前它只拿角色卡、Persona、生图角色库和这一面写的逐人外貌，读不到这张卡绑定的世界书；多人卡的长相写在世界书里，就只能靠这一面有没有写。现在规划时也会从这张卡绑定的世界书里取这一面提到的人物条目（和副 API 写面时同一套：按名字找、只留写长相的那几段、最多 3000 字），角色库和角色卡没写的外貌从这里补。

## 1.73.12 生图要求逐人写清长相

- 每个人的长相（发色发型、瞳色、辨识特征）要写在逐人外貌那一条里，生图才会把它配给这个人。以前这一条只是「各加一条」，模型常常漏写，画面那一段又只写「深邃冷峻的面容」「清丽的少女」，生图就不知道发色瞳色，画出来对不上。现在改成「画面里有几个人就写几条，一个都不能少」，并说明长相写在这里、不写在画面那一段（写在画面里两个人的发色会混在一起）。自然语言和 NAI 4.5 标签两种写法都一样；开了生图 LLM 时，这一面也照样逐人写外貌，交给生图 LLM 参考。
- 全链路诊断「生图描述来源」那一行多写一项：每个图框的人物外貌写了几条，没写会标出来。

## 1.73.11 页码从 0 数的写法，翻页和横滑都认

- 1.73.10 只管了「没标页、靠样式显示页」的翻页。现在同一类都算上：页标好了、但页码圆点这类装饰的样式按 0 数的翻页，以及横滑区的样式按 0 数的，页码都照模型的数法写，圆点、高亮跟着对上；跨面继承记住的页码回来时也换算好，不会多翻一页。同一面里别的转盘、别的翻页按 0 数，不会把这一个也带成按 0 数。

## 1.73.10 自动巡逻能巡到副 API 的兔子镜；从 0 数页码的翻页能翻了

- 维修兔自动巡逻以前跟着酒馆「收到消息」那一下跑，那时副 API 的兔子镜还没生成出来，新面一直没被巡逻，待修样本箱也就一直是空的。现在副 API 的兔子镜生成好、挂上去以后，会对这一面再巡逻一次（只在开了自动巡逻时）；期间 Swipe、重说了就不巡。
- 翻页区没给每页标页面标记、只靠自己的样式按 `data-rm-index="0"`、`"1"`… 显示页的写法，以前点「下一页」不动。现在按样式把页认出来，页码照模型从 0 还是从 1 数的写法写；跳到第几页的按钮也一样。只点亮指示圆点的样式、实际是选择区的不会被当成翻页。
- 巡逻发现点了没反应的控件、却没能记进待修样本箱时（多半是本机存储满了），会直接说出来，不再只说「可用重说」。

## 1.73.9 势力条目里的 NPC 长相也读得到；重画没存进去会说清楚

- 开放世界卡常把一个势力的十几个 NPC 写在同一条世界书里（「某某势力与npc」），某个人的长相写在条目中间。以前出场人物条目加起来超过 3000 字时，每条只留开头一段，留下的是势力介绍，人物长相被截掉了。现在先在每条里找「这一轮出现过的名字、后面紧跟着写长相」的那几段，只留这几段；这一条自己的关键词命中的人名排在最前面，地名这类排后面。写了长相的条目排在前面，没写长相的（地图风貌这类）排后面、额度不够时先让出来。
- 内置生图「重画」画好了、却没能存进本机存档（多半是本机存储满了）时，以前照样说「画好了」，面板里还是 1/1、翻不到新图。现在会直接说没存进去，并写出本机存储被谁占着；镜面上先换成新画的这张。

## 1.73.7 生图读世界书里的人物长相更稳

- 人物条目没写关键词（常驻条目），或者标题写成「【人物】阿雪」「阿岩·外貌」这种，以前认不出这一轮提到了他们，长相就没带上。现在把标题拆开，拆出来的人名在这一轮出现过也算提到；「人物、设定、外貌」这类分类词不算人名。
- 出场人物的条目加起来超过 3000 字时，以前排在后面的人物会被整条截掉（比如主角条目很长，第二个人的长相就没了）。现在每个人都留开头一段，长相一般写在前面。
- 设置里「最近请求」下面多一行「生图人物资料」：这次带了世界书里哪几条；没带的写明原因（卡没绑世界书、世界书被关、这一轮没提到、读取失败）。

## 1.73.6 外置兔子镜的正文有外框了

- 外置模式下标题是单独的一条标题条，模型给整面写的外框（底色、细边、圆角、阴影）以前被整个清掉，免得把标题条和正文框在一起，结果正文直接露在聊天背景上，看着很怪。现在把这个外框挪到标题下面的正文那一块：标题条照旧单独一条，正文用模型自己写的外框框起来。正文自己已经画了的那一项不补；正文分成好几块时不挪。
- 外框只在外置显示时画，不写进存档和收藏，切到内嵌模式不会框套框。

## 1.73.5 大富翁掷骰子棋子会走；标题和正文一样宽；多面也照样出图

- 大富翁、飞行棋这类走格子的面：以前掷骰子只换点数、棋子不动。现在掷出几点，棋子就往前走几格（走过终点从头接着走），格子上的事件跟着变。只认骰子结果是点数、旁边恰好有一排看得出是棋盘格子的写法，普通页签不会被当成棋盘。
- 电脑端外置兔子镜画面比聊天栏窄时，外壳收窄到画面本身的宽度，标题条跟着一样宽。以前标题条按整行算宽度，外壳收不到画面那么窄，标题比画面宽一截。手机端标题和正文本来就都铺满正文那一栏。
- 一次写好几面的回复，最后一面写到画面说明时不完整，也和单面一样补齐、图框留着照样出图，不再整面丢掉。
- 全链路诊断多一行「生图描述来源」：每个图框的画面描述是模型写的（几个字），还是模型没写、插件用标题和图框旁边的字补的，以及有没有出图。

## 1.73.4 图框一律留着

- 画面描述没写出来（模型漏写、或写到这里被截断）的图框不再拿掉：插件用这一面的标题和图框旁边写的字当画面，照样出图。以前这种图框会被删掉，看起来像这一面没打算出图。

## 1.73.3 画面说明没写完整时尽量照样出图

- 1.73.2 以前，回复在画面说明这里不完整，就把对应的图框整个拿掉、提示「这一面先不配图」，看起来像这一面根本没打算出图。其实很多时候只是模型漏写了结尾的 `</div>`，或者画面描述已经写了大半。现在：只是漏了结尾标签的，补上，图照画；截在画面描述中间、但已经写了 20 字以上的，补齐后照样拿去画；只有画面描述几乎没写出来，才去掉图框并提示「还没写出画面描述就被截断了，这一面没有图」。

## 1.73.2 不再误报「画面说明被截断」；切换按钮、调光滑杆、页签选中有反应了

- 「兔子镜写到画面说明时被截断了，这一面先不配图」以前只要回复少了结尾标签、或模型写了画面说明却没放图框，也会弹出来，看着像每面都被截断。现在只有真的去掉了一个图框（这一面因此少了一张图）才提示。
- 「拉动锦绦（拨换昼夜室光）」这类没写动作的切换按钮：样式里写好了 `[data-xxx="dim"]`、`[data-xxx="candle"]` 几种状态、却没人写这个属性时，按一下轮着换。调光、换档这类滑杆也一样，拖到哪一段就写哪个状态词。模型自己写了这个属性的不碰。
- 一排「春／夏／秋／冬」页签（label 包着藏起来的单选）、样式里一条选中样子都没写时，给当前选中的那个页签描一圈，至少看得出选了哪个。

## 1.73.1 「挂在哪一层」的选项挪到显示模式页

- 1.73.0 新加的「外置兔子镜挂在消息的哪一层」写在了旧设置面板里，新版设置界面把那一块藏起来了，找不到。现在放在 设置 → 兔子镜显示模式 里，「外置展示／跟随正文内嵌」下面，三个选项和上面一样是卡片样式。

## 1.73.0 外置兔子镜挂进消息里，不再掉到美化的气泡外面

- 以前外置兔子镜挂在整条消息的后面（和消息平级），美化把正文或整条消息画成气泡／卡片时，兔子镜就掉在气泡外面。现在默认挂进这条消息里：美化把气泡画在正文上，兔子镜就挂在正文最后面、跟着进气泡；否则挂在正文下面、还在这条消息里，整条消息画成卡片时也在卡片里。宽度直接铺满正文那一栏，不再量位置。
- 设置里「独立 API 生成方式」下面新增「外置兔子镜挂在消息的哪一层」：自动（推荐）／一律放进正文气泡里／放到整条消息外面（1.73.0 以前的位置）。兔子镜掉到气泡外面了选第二个；不想被美化的卡片包住选第三个。
- 正文正在流式输出、正在编辑的那一层先放正文下面，写完／编辑完自动挪进正文；改设置后已经显示的兔子镜会跟着挪，不另造一份。
- 全链路诊断的「手机端排版」一节多一行「外置挂法」，写明挂在哪一层。
- 复核后补的：酒馆整段重写正文（翻译、正则重渲染、编辑）时挂在正文里的壳会原样挂回去，镜面里点过的状态不丢；手机宽度下不会留着桌面量出来的收窄宽度；维修兔诊断不把挂在正文里的兔子镜当成正文的一部分。

## 1.72.9 今日更新汇总（1.70.9 → 1.72.9）

- 【1.72.9 有声书／播放器的进度条会走了；样本箱不再记插件自己的失败卡】动画区域里只有一根进度条和播放键、没写会动的部件时：按播放进度条自己往前走（约 30 秒走完），再按暂停；播放键两边没写动作的按钮按位置当快退／快进，各跳十分之一。自动巡逻不再把「生成失败」那张卡（找回旧兔子镜／重新生成／挨打猫）当成模型写的面记进样本箱，以前误记的也不再列出和导出。
- 【1.72.8 收藏夹去重认得出同一面】以前只认「内容一字不差」：同一面收藏时图框正好显示「正在画」、画面说明位置不同、或点过开关数字变了，就认不出是重复。现在这些都不算差别，同一角色、同一标题、文字几乎一样的也算同一面（留最早那份）；去重做完立即收起「再点一次确认」，不会多点一下又报「没有重复」。
- 【1.72.7 生图读得到世界书里的人物长相】多人卡、开放世界卡的角色卡里只有世界观，人物长相写在卡自己绑定的世界书里，兔子镜写画面说明时看不到，只好自己编（比如把银发写成黑发）。现在开着内置生图时，会从这张卡绑定的世界书里取这一轮和前两层提到的人物条目（关键词或标题对得上名字的），单独交给模型写人物外貌和衣着，最多 3000 字，没提到的不带。打开「自动参考当前角色主世界书的已启用条目」时整本照旧读，并把出场人物的条目排在最前面，免得长世界书被截断时截掉他们。
- 【1.72.6 酒馆连接配置换来换去，兔子镜不再拿错 key】兔子镜选的连接配置如果保存时没勾 Secret，酒馆会拿「当前正文正在用」的 key 去请求，正文一换配置，兔子镜就报 Invalid token、拉不到模型。现在这个配置在酒馆里被切到、或在 key 管理里选 key 时，兔子镜记下它当时用的是哪把 key（只记编号，不读 key 本身），之后按它发请求、拉模型都带上；那把 key 删了就不用。还没记下时报错会直接说明原因和解决办法。
- 【1.72.5 生图被审核截断时只丢图、不丢面】画面说明改到每一面的最后写（`<div data-rm-draw-notes="1" hidden>`，插件按编号收回图框）。模型写到这段被服务商内容审核截断时，这一面照常显示、只是不配图，以前整面作废只能重说。生图提示词的内容不变，旧的兔子镜照旧能用。
- 【1.72.4 正文被美化包起来时也能生成】有些状态栏／正文美化把整层正文画进卡片、内嵌页面，兔子镜以前报「当前正文读出来是空的」。现在改读这一层的消息原文，思考内容和设置里勾了跳过的标签照样去掉。
- 【1.72.3 同类写法都接上】「做完几步／翻到第几页／输了几位／转到第几档／连了几对／滑杆第几档」才显示内容的面，各种写法都能正常显示。密码锁多认几种写法：▲▼ 夹一个数字、「密码：739」连写、要按「开锁」才开（按错转轮闪红）；没有密码的数量加减不会被当成密码锁。
- 【1.72.2 密码箱和种花小院】密码箱转轮能拨动，转到提示的数字就开锁、露出暗格内容；种花小院做完三步，花会长出来、揭晓卡会出来。
- 【1.72.1 深色切页条】深色的面，底部切页条也是深色，不再挂一块白条。
- 【1.72.0 接上千千结长期记忆】「高级设置 → 共同回忆资料来源」勾选「千千结（长期记忆）」后，抽到「共同回忆」主题会用千千结的记忆来写；独立 API 生成、重说、补楼都能用。
- 【1.71.3 许愿柳挪到悬疑/怪谈】它是恐怖片里的禁忌诅咒物，原来误放在温馨的仪式感里，新编号 H.0.2。以前对它做过的黑名单、收藏设置需要在新位置重新点一下。
- 【1.71.2「正文已出，立即生成」不用等状态栏写完】以前状态栏还在输出时点它会被安全阀拦下，现在正文出来就能点。
- 【1.71.1 多面镜子来回翻，生图不再重画】以前翻回画好图的那一面会重画一遍、白花一次额度，现在认得回原来那张图。
- 【1.71.0 维修兔自动巡逻会攒样本】开着「维修兔自动巡逻（实验性）」时，新生成的兔子镜会在后台把每个按钮试一遍，按了没反应的自动记进「待修样本箱」（不含聊天内容），攒几面后到 设置 → 工具 导出发给作者。又修好一批点了没反应的写法；存档里的兔子镜重新打开后开关能正常关回去。
- 【1.70.11】捏脸这类「按住看原貌」的面，按住时原图会出来；只有一个按钮的效果区，「按下后才出现」的那段平时先藏着。
- 【1.70.10】天空色谱这类滑杆面，拖到对应档位卡片会出来。
- 【1.70.9 一批点了没反应、内容不出来的写法】一排「第一站／第二站／第三站」按钮点哪个看哪块；几个单选共用一种样式时结果一一对上；开关两个场景各显示一个；「拉开窗帘」「摸摸小猫」按哪个出哪段；校准方位按下图标转一圈；答对才出现的小徽章会出来；口令按对前后各显示对应的那句。
- 以上交互修复对旧的兔子镜同样生效。下面是各版本的详细说明。

## 1.72.8 收藏夹去重认得出同一面

- 图框提示、画面说明位置不同、点过开关几个字不同的同一面，也算重复收藏（同角色同标题、文字几乎一样），留最早那份；去重后立即收起「再点一次确认」。

## 1.72.7 生图读得到世界书里的人物长相

- 开着内置生图时，从这张卡自己绑定的世界书里取这一轮和前两层提到的人物条目，单独交给模型写人物外貌和衣着（最多 3000 字）。打开「自动参考当前角色主世界书的已启用条目」时整本照旧读，出场人物的条目排在最前面。

## 1.72.6 酒馆连接配置换来换去，兔子镜不再拿错 key

- 兔子镜选的连接配置如果保存时没勾 Secret，酒馆会拿「当前正文正在用」的 key 去请求，正文一换配置，兔子镜就报 Invalid token、拉不到模型。现在这个配置在酒馆里被切到、或在 key 管理里选 key 时，兔子镜记下它当时用的是哪把 key（只记编号），之后按它发请求、拉模型都带上；那把 key 删了就不用。

## 1.72.5 画面说明挪到面的最后，被审核截断时只丢图、不丢面

- 画面说明改到每一面的最后写（`<div data-rm-draw-notes="1" hidden>`，插件按编号收回图框）。模型写到这段被服务商内容审核截断时，这一面照常显示、只是不配图。生图提示词的内容不变，旧的兔子镜照旧能用。

## 1.72.4 正文被美化包起来时也能生成兔子镜

- 有些状态栏／正文美化会把整层正文画进内嵌页面、卡片或图片里，页面上一个能读的字都没有，兔子镜就报「当前正文读出来是空的」、生成不了。现在遇到这种情况改读这一层的消息原文：看不见的部分、设置里勾了跳过的标签照样去掉。页面上读得到字时还是照旧读页面；是「跳过指定标签」把整段吞掉的，仍按原来的说明提示。

## 1.72.3 同类的数字状态、各种写法的密码锁都接上

- 「完成几步／第几页／输了几位／第几档／连了几对／滑杆第几档」这几类，样式里用自己起名的 `data-xxx="N"`、`.前缀-N` 类，或「紧跟在后面的那块」写法来显示内容的，现在都会同步写过去。只改这个区域里面的元素，模型拿来当编号的属性、面上别处在用的类不碰。
- 密码锁多认几种写法：▲▼ 两个按钮夹一个数字、密码连着写（「密码：739」）、解锁写成类（`.box.unlocked`）、样式没写解锁状态但后面藏着一块内容、要按「开锁」才开（按错了转轮闪红）。没有密码的数量加减不接；锁必须是包着转轮的那块，面上别处的菜单、待办不会被「打开」；开过一次的锁重新打开面时沿用，不会去开别的东西。

## 1.72.2 密码箱转得动、能开锁；种花小院的花会长出来

- 密码箱（几列「拨动 ▴」+ 一位数字的转轮 + 「提示：七 · 三 · 九」）：模型写的脚本被拿掉后按了不转、也开不了锁。现在按一下转一格，转到和提示一样的数字时，把样式里写好的「解锁」状态打开，暗格里的内容就出来了。
- 种花小院这类「按顺序做三步」的面：样式写的是 `data-rm-step-val="3"` 才长出花、出揭晓卡，而插件只写了完成步数，花一直不长、卡片不出。现在完成几步就同步写到样式要的那个属性上，连「紧跟在后面的卡片」这种写法也能对上；复位时一起退回去。

## 1.72.1 深色的面，底部切页条也是深色

- 切页条放在底部时，以前一律是白底深字，深色的面下面挂一块白条很扎眼。现在按这一面自己的底色（面本身、标题栏或正文第一层的底色）判断深浅：深色的面配深色切页条，浅色的面照旧白条。

## 1.72.0 接上千千结（ST-MyriadKnots）长期记忆

- 「高级设置 → 共同回忆资料来源」扫描时能认出千千结，显示为「千千结（长期记忆）」，勾选后抽到「共同回忆」主题时会把它的记忆交给兔子镜当回忆杀的资料。
- 读的是千千结公开的只读接口：优先读这一轮它为正文准备好的「前情」和「相关记忆」（跟当前剧情最相关）；这一轮没准备材料时（比如刚打开聊天），再读一次它的整份记忆，最多等 6 秒，读不到就不用。
- 只读当前聊天：千千结关着、当前聊天还没准备好、或读到的是别的聊天，都不用，也不会让千千结去整理或补任何东西。
- 别的插件接口只在跟随正文模式下读；千千结的材料本来就是给正文生成之后读的，所以独立 API 生成、重说、补楼也能用。
- 「测试读取」这一轮没有材料时会说明「正式生成时会改读整份记忆」。

## 1.71.3 许愿柳挪到悬疑/怪谈

- 主题「许愿柳」原来放在 C 温馨/日常 → 仪式感（编号 C.1.6），和求婚、婚礼、纪念日排在一起，说明也写成了温馨的祈福道具。它本来是恐怖片里的禁忌诅咒物，现在挪到 H 悬疑/怪谈 → 规则怪谈/诅咒物品下，编号改为 H.0.2，说明改成：愿望都会实现，但实现方式扭曲、代价落在许愿人或身边的人身上，并随许愿次数升级成恐怖后果。
- 以前在黑名单、收藏里对旧编号 C.1.6 做过的设置不会跟过来，需要的话在新位置重新点一下。

## 1.71.2 「正文已出，立即生成」不再被安全阀拦到状态栏写完

- 自动生成时，正文写完就可以点「正文已出，立即生成」先出兔子镜。这个按钮以前按「自动生成」过安全阀：状态栏、小总结还在流式输出时，整条消息里有没写完的标签，被当成「正文截断」拦下（只提示一次，之后再点就没反应），只能等状态栏全部写完。现在它和手动生成一样，是用户自己点的，不再过安全阀。自动生成照旧会拦异常正文。

## 1.71.1 多面镜子来回翻看时内置生图不再重画

- 一面镜子里有好几个小剧场时，画好的图存进本机用的是「聊天＋楼层＋swipe＋图框＋提示词」做名字。可每一面的楼层、swipe 要等外壳挂好后才写上，画图常常在那之前就开始了；聊天名前后也是两种写法（没写上时是聊天名，写上后是 `chat:聊天名`）。于是同一张图先存在一个名字下，之后再翻到这一面时按另一个名字找，找不到就又让柏宝绘画一遍，小兔子的生图面板里也显示「这一页没有图」。
- 现在：这一面还没写上归属时直接读外壳上的归属；找图时同一聊天、同一图框、同一段提示词的图，楼层或 swipe 有一边当时还没记上的也算同一张（两种聊天名写法也认），以前已经存在旧名字下的图也能找回来、在面板里翻历史和重画；同一张正在画的时候再挂一次，跟着那一次等结果，不再另发一次请求（一口气生成很多楼时排队的图也少了重复的）。

## 1.71.0 维修兔自动巡逻会攒样本；状态桥一次修一类写法

- **自动巡逻记样本**：开着「维修兔自动巡逻（实验性）」时，新生成的兔子镜做完安全修复后，会在隐藏副本里把每个控件都试一遍（不碰真实控件）；按了画面没变化的，自动把写法骨架记进「待修样本箱」（文字全是占位，不含聊天内容），兔子图标上写明哪几个没反应，第一次记到时提醒一句。攒几面后到 设置 → 工具 导出，一批发给作者加进维修库，不用再自己一个个找。实测会跳过本来就不该有反应的：前面操作已经藏起来的控件、滑杆和文字框的说明文字、当前页的分页按钮、已被认定「没写结果」的按钮、赞同／评论／收藏这类装饰按钮。
- **状态桥**：驱动把状态写在区域自己身上（开关的 `data-rm-on`、按住的 `data-rm-active`、翻页旋钮的 `data-rm-index`…），模型的样式却常把状态条件写在别的位置——区域里面的某一层（`[data-rm-ui="hold"] [data-rm-active="true"] .原图层`）、区域外面同时包着开关和内容的那一层（`[data-rm-on~="open"] .抽屉`）、里面的元素自己身上（`.灯[data-rm-on~="on"]`）、并排的面板（`.面板[data-rm-picked="a"] .a`）。以前这类写法一种认一次，现在统一按样式写的位置把状态同步过去，值原样照抄、不猜内容；几个区域写同一层时各记各的，模型原本写在那一层的值保留，自己写的记在 `data-rm-bridged` 上，存档带回来也认得。
- **存档带回来的痕迹不再卡住交互**：开关上上次补写的 CSS 词（`unsealed`）、开着时写上的属性程序（`data-rm-state="reverse"`，现在带 `data-rm-program` 记号）、刮开遮蔽时让开的内联颜色，重新打开后都能正常关回去；维修兔的隐藏副本也会拿到驱动改写前的内联原值，不再误报「切换没有变化」。
- **按钮类名带号码的分段**：一排没写动作的按钮类名带着号码（`…-stage-1`、`…-stage-2`），样式写着 `.sheet[data-scale="1"] .tier-1{display:block}`：点哪个就把号码写到外层的那个属性上。
- 遮蔽文字（`data-rm-spoiler`）的内联 color 和 background 写成同色时，刮开后让开这两项，字看得见；盖回去恢复。
- 累积区里「每一项自己的卡片」（`.card[data-rm-done="true"]`）仍由部件镜像按项写，不会被区域的整体状态盖掉。
- 状态桥只把样式点名的词同步到载体上（`[data-rm-on~="item1"]` 就只写 `item1`），区域上别的词不带过去，免得误触载体下别的开关的规则；别的区域里面的元素一律不碰。

## 1.70.11 捏脸面的按住看原貌、只有按钮的效果区

- 按住区域：模型的样式写 `[data-rm-ui="hold"] [data-rm-active="true"] .原图层`，要求「按住」状态写在区域里面包着原图层的那一层上；插件以前只写在区域本身和按钮上，原图层永远出不来。现在按住时也把状态写到区域里包着这些目标的那一层，松开撤掉。
- 效果区只写了一个 `data-rm-fire` 按钮和一段 `data-rm-show="changed"`（没有任何部件）：以前整组不接线，「按下后才显示」的那段一开始就露着。现在按下按钮就算一次变化，那段平时藏着、按下才出现。

## 1.70.10 天空色谱的档位卡片不显示

- 滑杆是整数档（如 0–4），模型的样式写 `[data-stage="2"] .卡片{display:block}`，却没有任何东西把档位写到 `data-stage` 上，所以拖滑杆卡片一直不出来、天色也不变。现在滑杆调节区会认出样式里这种「非插件的 data-xxx=整数」祖先条件，把当前档位同步写到包住这些目标的最近祖先上（区域自己包得住就写区域上）。

## 1.70.9 一批点了没反应、内容不出来的写法

- 累积收录：按过某一项后，对应那段说明（data-rm-show 写的是那一项的键）现在会出来，以前按了也不显示。
- 顺序口令：模型把整串答案原样写进显示条件（「未解锁／已解锁」两句），以前两句都藏着，现在按对前后各显示一句。
- 一排没写动作的按钮（「第一站／第二站／第三站」），后面跟着同样多块、只显示第一块的内容：现在按顺序接成分页，点哪个看哪块。
- 几个单选共用一个类名、结果块隔着按钮排在后面：以前选一个会把所有结果都放出来（或一个都不出），现在按顺序一一对上；旧存档里带着的旧接线会自动换掉。
- 同一个按钮既记一笔、又要弹出说明：以前弹窗被拦住，现在两样都有。
- 开关两个场景都自带隐藏：以前开着、关着都是空的，现在各显示一个。
- 「拉开窗帘」「摸摸小猫」这类按钮对着同名的一段话：以前几段话一打开就全摆着，现在按哪个出哪段。
- 「校准方位」这类按钮要给图标挂一个转动的样式：现在按下会转一圈；输入答对才出现的小徽章也会出来了。
- 诊断里不再把兔子镜自己加的排版标记当成「不认识的写法」。
- 以上旧的兔子镜也生效。

## 1.70.8 台标、字幕条不再压住正文

- 修复一类字显示不全的写法：屏幕、监视器这类画面里，模型把台标贴在左上角、把字幕条贴在底部（绝对定位、带不透明底色）。切到图片时压在图上没问题，切到文字内容时就压住了标题和最后几行。
- 现在兔子镜会量一下：这类贴边小条压住了正文的字，就给画面在那一边补出空位，字往里让，台标和字幕还在原处；只压着图片、半透明水印、整块遮层的不动。每次点按切换后重新量，切回图片时空位撤掉。旧的兔子镜也生效。

## 1.70.7 Bingo 卡连成一线有反应了

- 修复 Bingo 卡连上了也没动静：模型常只写了「点一格盖章」，没写三格连成一线之后的反应。
- 现在维修兔认得这种格子：连成一线（横、竖、对角）时那几格描一圈朱红，新连上一条时格盘中央盖一枚「连成一线」（两条就是「连成两线」），过一会儿淡出，不挡点按；取消勾选断了线，描红跟着撤掉。只接看得出是 Bingo、方方正正、每格一个勾选框的格子，普通勾选清单不动。旧的兔子镜也生效。

## 1.70.6 转盘下面另框写的说明也会跟着换

- 修复一类转了不换内容的写法：转盘（拨盘）在上面，每一格对应的说明写在下面另一个框里，不在转盘的范围里面。以前转盘能转、格号也记下了，下面的说明却一直停在第一格。
- 现在这一面只有一个转盘、开关这类驱动时，写在它外面的「第几格显示什么」也归它管，转到哪格就显示哪格；一面里有两个以上驱动时不乱认，照旧不动。旧的兔子镜也生效。

## 1.70.5 同名的两套单选也能点了（捏脸、换装这类）

- 修复一类点了只变色、画面不动的写法：模型在最上面放了一排带编号的隐藏单选给样式用（选中「霜白」就换发色、出对应的对白），每个选项胶囊里又各放了一个同名的单选。两套同名就成了一组，点胶囊会把上面那个对应的取消掉：胶囊变色了，发色、瞳色、对白都不动。
- 现在维修兔认得这种写法：把胶囊那一套和上面那一套按顺序一一对上，点胶囊就切到上面对应的那个；两套不再互相取消。只在两套一样多、上面那套确实被样式按编号使用时才接。旧的兔子镜也生效。

## 1.70.4 开关的状态名和模型自己的 CSS 对不上时也能点开

- 修复一类点了没反应的写法：模型自己的样式里写好了「哪个状态词显示哪块内容」（比如封印破了显示托盘、点「看一」显示详情一），开关却写了样式里没有的名字（比如写成选择器），或者状态词写对了、却只挂在按钮自己身上，管不到旁边的内容。
- 现在维修兔照模型自己的样式来认：开关区域里只有一个没被别的按钮认领的状态词，就按它；按钮点名的状态词管的内容在按钮外面，就把这个词写到同时包着按钮和内容的那一层上。诊断里不再报「显示条件对不上」。旧的兔子镜也生效。

## 1.70.3 点「有更新」先看公告，不会直接更新、刷新

- 兔子亮了点开想看更新公告，结果页面直接刷新了：手机上点「有更新」的那一下，可能会落到刚弹出来的「确认更新」上。现在「确认更新」要等更新公告显示出来、再过一小会儿才能点，一定先看到公告。
- 酒馆里的兔子镜文件已经是新版时（别的设备点过更新、或者酒馆自己自动更新了），以前会直接刷新页面；现在只弹一条提示「兔子镜已经更新到某版，点这里刷新」，什么时候刷新由你决定。
- 自己点「确认更新」以后，更新完还是会自动刷新一次（新代码要刷新才生效）。

## 1.70.2 快拍里标出「正文已变」的那几面

- 快拍和聊天里的兔子镜用的是同一份存档，但以前判断不一样：聊天里只挂「对着这一层现在的正文生成的」那面，快拍只看楼层号。换回以前的存档、或者改过正文以后，快拍里还列着那一面，点进去跳到那一层却看不到，像是存了两份。
- 现在快拍用和聊天同一个判断：对不上的那面照样列出来（快拍是唯一能看到它的地方），但标上「正文已变」；点进去跳到那一层时说清楚为什么聊天里没挂，想挂回去可以在那一层的卡上点「找回旧兔子镜」。

## 1.70.1 正文生成失败后兔子镜卡不再一层层叠起来

- 正文生成失败时，酒馆会把没写完的那条回复删掉。以前兔子镜在那条回复下挂的「生成失败」「旧镜面待恢复」卡不会跟着拿掉（为了 TT 短暂把楼层移出页面时不丢「重新生成」入口，这两种卡特意留着），下一条回复落在同一个楼层号时又被挂回来，失败几次就叠几张。
- 现在按聊天记录判断：这条回复已经不在聊天里、或者这个楼层号现在是另一条回复，它留下的没画好的卡就拿掉；回复还在、只是暂时不在页面上的照旧留着。同一层只留一张没画好的卡。画好的兔子镜不受影响。
- 已经叠起来的，正文再生成一次、删一次楼层或刷新页面就会清掉。

## 1.70.0 一键补楼层能补老楼层；美化备份不再拖慢保存；生图发色不再打架

- 一键补楼层：以前还没加载到页面上的老楼层补不了，要自己往上翻。现在也一起排进来，补到那一层时先在聊天里把它加载出来（和点「显示更多消息」一样），再照常生成；开始前会说有几层是这种老楼层，楼层很多时手机上可能会卡一会儿。反正要跳过的楼层（已经有兔子镜、正文像出错的）不先加载；酒馆正在生成时先等着再加载；加载途中点暂停或停止就不再往上加载，这一层也不发请求；切到后台也照样接着补。加载完会重新确认开关、聊天、楼层有没有变。
- 导入的美化：以前为了重启不丢，整份美化存在酒馆设置里，酒馆每次保存设置都要连它一起上传，美化大的话每改一个开关都慢一点。现在美化单独存成酒馆里的一个文件，设置里只记一个小记号；以前存在设置里的会自动挪过去。连着改几下只传最后一版；很大的美化现在也能备份了；宿主不让存文件时退回原来的办法。
- 几台设备共用酒馆里这一份美化：每次打开页面先和酒馆那份对一下（对完之前设置里的美化框锁着，显示「正在和酒馆里存的美化对一下」），以酒馆那份为准——别的设备存了新的，这台刷新后就换上；只是打开页面、或者在旧版上点一下，都不会把旧美化传上去盖掉别的设备存的。一时读不到酒馆那份时照样能改，改的先只存在这台设备上，下次能读到时再传；要是那期间别的设备也改过，就用酒馆里那份，这台改的那版另外留着，设置里能一键换回来（本机放不下另一份时，先留着这台的、不传，设置里让你选用哪份）。升级前某台设备本机留着、和酒馆里不一样的美化，那台设备继续用自己的，在那台上存一次后再一起同步。点过「恢复默认设置」也照样能从酒馆找回。
- 内置生图：角色库标签和模型写的标签合在一起时，发色、瞳色、头发长短这几样以角色库为准，模型写的不同说法不再一起交给生图（以前角色库写 silver hair、模型写 white hair 会两个都发，发色容易画乱）。dark hair、platinum blonde、多色、渐变、挑染、肩长这些写法也认得。衣着、发型、表情照旧用模型写的。
- 清理：删掉 13 个早就没在用的旧规则文件；浏览器测试没装 Edge 时改用 Chromium。

## 1.68.100 内置生图：人物写上衣着

- 没开生图 LLM 时，图框里每个人那一条除了长相，还要写这一幕穿的衣服和身上的配饰；正文或这一面写了就照写，没写就用角色卡里常穿的衣着。英文标签放宽到 4～10 个，里面要有衣着；和画面里写的衣着保持一致。
- 以前在柏宝绘角色库或智绘姬角色预设里配了某个人，模型写的这个人的标签整串不用，衣着也跟着丢了。现在角色库的标签放前面，模型写的接在后面，一模一样的去掉（意思相近、写法不同的两边都会留着，比如 silver hair 和 white hair）。

## 1.68.99 生图规则回到 1.68.95 那版；分页点了是空白的修好

- 没开生图 LLM 时的内置生图规则改回 1.68.96 之前那一版（画面约 100～200 字、人物写稳定外貌）。1.68.96 的放宽实际画出来没有以前好看，衣着也读得不好。
- 有一种分页写法以前点哪一页都是空白：模型把每页先藏起来，只给带「当前页」记号的那页显示，兔子镜切页时没挂上这个记号。现在切到哪页，就照模型的写法给那页挂上记号，切走时再撤掉（只挂记号，表格行、窄屏故意藏起来的都还按模型自己的样式）。

## 1.68.98 像素小屋：小人画全身、位置不再错

- 第一次实测发现两个问题：说明里举的小人例子只有 5 行（一个脑袋加一条衣服），模型照抄了，每个人都是一样的小脑袋；模型还把「第几格」又抄成了以像素为单位的位置，小人被挤到角落、上下错开。
- 说明里的例子换成一颗小心心，并写明人物画全身（头发、脸、身体、手、腿和鞋，约 10～14 格宽、16～22 行高），每个人按自己的样子画，不照抄。
- 写了第几格的小人，兔子镜按格子摆，模型另写在它身上的左右、上下位置不再算数；点了换位置的写法照样生效。

## 1.68.97 新展现形式：像素小屋（字母像素画）

- 「可视化小剧场」里新加 10.2.32 像素小屋：横版像素游戏画面，屋子、家具、两个人和小动物都是像素画。
- 新写法「字母像素画」：模型用一行行字母画人物、小猫、小物件（一个字母一格，点是透明），再写上每个字母是什么颜色，兔子镜把它画成整齐的像素方块，放到场景里指定的那一格。场景放大缩小时，小人跟着一起缩放，和背景对得齐。
- 以前让模型直接写坐标画像素，它只肯画几块大色块，人看不出是谁；用字母画，发型、眼睛、衣服、手里拿的东西都画得出来。
- 只在抽到像素小屋时才告诉模型这种写法，别的面不多发字。

## 1.68.96 内置生图：画面写足、画风跟着展现形式走

没开生图 LLM 时，写兔子镜的那次请求顺手写的生图提示词改了几处：
- 画面描述从约 100～200 字放宽到约 150～300 字，衣饰小物件、花瓣火星这类细节写足。
- 以前不让写比喻；现在比喻和象征可以写，但要先变成画得出的东西（比如两人的影子融成一柄剑）。对白和心理活动仍然不写。
- 画面开头和标签里按这一面展现形式本身的样子写出画风和媒材：水彩绘本就写水彩，杂志封面就写杂志。不给固定的画风清单。
- 人物外貌标签除了发色、瞳色这些，也可以写年龄、气质和标志性衣着（这一幕换了衣服时以当时衣着为准），数量从 4～8 个放宽到 4～10 个。
- 开了生图 LLM 的不受影响。

## 1.68.95 一键补楼层

- 设置 → 缺壳扫描下面新加「一键补上没有兔子镜的楼层」（使用独立 API 时）：扫描范围里没有兔子镜的回复排好队，从最早那层开始一层一层生成，不用再一张张点卡。
- 开始前先说清楚要补几层、每层几面、至少发几次请求，确定了才开始。
- 一次只发一层，每层之间隔几秒；酒馆正在生成正文、或别的兔子镜还在生成时先等着，不跟它们抢。
- 随时能暂停、继续、停止（停止时这一层照常收尾，不再发下一层）。关掉设置界面也照样在补，再打开能看到进度。
- 已经有兔子镜的层、正文太短像是出错的回复、中途删楼后挪了位置的层都自动跳过，并写明原因。
- 生成要读页面上显示的正文，还没加载到页面上的老楼层这次补不了：开始前会说有几层，在聊天里往上翻把它们加载出来再点一次就行。
- 连着 3 层都没成功就自动暂停，并写出最后一层的失败原因；换了聊天就停，不会补到别的聊天里。补完告诉你成功几层、哪几层没成，没成的层下面挂着卡，可以单独再点。

## 1.68.94 美化重启后不再丢

- 美化框里改了字，停手一会儿就自动保存，不点「保存并应用」直接关掉、刷新或导出也不会丢；点「导出」时也会顺手保存一次。
- 美化除了存在这台设备上，还在酒馆的扩展设置里留一份：浏览器或宿主清掉网页数据、重启后本机那份没了，会自动从酒馆设置里找回。特别大的美化（比如带很多内嵌图片）只存在本机。

## 1.68.93 按正文挑签不再总选第一张

- 按正文挑签时，规则里虽然写了「不默认选签 1」，但同一份规则后面的「真实用法」和写法清单（比如「鼓掌」「点开回忆一段」配哪种写法）都是按签 1 的展现形式给的，其他几张签没有。模型拿到这些现成的用法，几乎总选签 1。
- 现在挑签的面不再给按签 1 配的真实用法，写法清单也不按某一张签的用法配，几张签站在同一条起跑线上；也不会在这种面上接收藏的续篇（续篇会把签 1 的形式换掉）。普通抽签的面不受影响。规则反而短了一点。

## 1.68.92 选签理由：更多写法也认得出

- 复查 1.68.91 时补的：选签理由里有 & 这类符号、有 *强调* 这类写法（酒馆显示时会变样），或者被酒馆包成了一个段落时，以前认不出、还会露出来；现在都能认出来拿掉。标题后面第一段是模型自己写的正文时照样不动。

## 1.68.91 选签理由不再露出来；纹理写在形式本体上

- 「按正文挑签」时，模型在标题后面写的选签理由和签号（给兔子镜读的）在跟随正文生成时会被酒馆露成正文开头的一段字，比如「正文停在……选签1……1」。现在显示时按原始消息认出来拿掉；对不上的正文不动。这个问题从挑签功能有的时候就在。
- 材质纹理的规则：以前写「写在这一面最像实物的主体或承载面上，一面只写一处」，模型常挑整面的底板，纹理落不到展现形式上。现在写「写在展现形式本体那件东西上，不写在包着它的底板、外框或背景上」，一面最多三处，不同的实物各写各的（比如一张名片和一本手账各是各的材料）。规则多 12 个字。

## 1.68.90 弹窗回来了

- 1.68.78、1.68.79 为了不让每面都是「切换按钮＋几个弹窗」，一下加了三道：每面的交互规则写了「不另开小框补内容」，方案 2 写了「不用点开的小框」，写法清单在最近两面有一面用过切换或弹窗时就不给这两种。三道叠在一起，弹窗几乎不出现了。
- 现在去掉前两句（交互规则和方案 2 不再说不要小框）；写法清单只在最近两面「都」用了切换或弹窗时才换口味，一份清单里仍然不同时给切换和弹窗。弹窗照常能出，只是不会每面都是它。规则少了 13 个字。

## 1.68.89 SVG 画的东西也能铺纹理

- 以前材质纹理只能铺在普通的块上；画面里用 SVG 画的东西（人物、动物、小物件）铺不上，因为它们没有可以叠纹理的那两层。现在模型把纹理描述写在 SVG 里那一组图形上也行，兔子镜用滤镜直接作用在这组图形上：表面加上和其他地方同一套的颗粒（形状、方向、粗细、浓淡照写的来），光从左上来，只在图形里面。
- 写「纤维 哑光」时，这组图形的轮廓会变软、带一点不规则的边；粗细决定边的长短（细的短、粗的长），按图形大小封顶，小图标不会糊掉；写「很淡」时只改轮廓、不加颗粒。SVG 坐标放大缩小都按屏幕上的实际大小换算，看起来一样。
- 模型自己给这组图形写的滤镜（比如投影）会接在后面一起生效，不会被盖掉；这一面收着时，展开后再铺；关掉开关就撤掉。
- 规则多一句「SVG 里画的东西写在它那一组上也行」（16 个字）。

## 1.68.88 第二轮复查修正

- 写了纹理的那块收在模型自己写的小折叠里时，展开小折叠后，盖在它上面的板子以前不会补铺纹理（在一些手机、Safari 上能看出来），现在会。
- 「重新生图」沿用旧提示词时，以前没写标签行的那种画面描述会被当成标签打乱，现在不会。标签写法里人物行「名字: 外貌标签」的名字留在最前面。
- 美化：字符串里有 /* 时（比如 content:"/*"），以前会把后面的规则吞掉；@import 后面不带空格直接写引号的也能认出来了。
- 纹理的样子和「近几面用过」按「这一面里第几处」算：单独铺一面和整个聊天一起铺，同一处纹理一样，也不会重复记。打开开关、截图时铺旧画面，不算进「近几面用过」。
- 存档、收藏时从页面上抄回来的纹理数据（很长的纹理图），重新显示时去掉，不让存档越来越大；模型自己的样式不动。
- 里面东西特别多的板子不再一个个量（太慢），不铺纹理。模型写的画面不能冒充美化认的工具弹窗名字。

## 1.68.87 复查修正；材质不再每面一样

- 材质每面看起来一样：1.68.81 把「近几面用过什么，这一面换一种」改成只提材料名，模型就只换名字、粗细形状照抄，兔子镜画纹理只看粗细形状，画出来就一样。现在提醒里带上样子，比如「旧宣纸（细 横 条纹 淡 哑光）」，并要求粗细、形状、光泽跟着换。粗的「斑块」以前几乎看不见，现在起伏加高了。
- 一块东西自己写了纹理、外面那块又铺过来时，以前里面那块会被外面的盖掉（自己的光泽、形状都没了），现在保留它自己的。
- 这一面收着、等展开再铺纹理时，认的是整面的折叠，不是模型写在里面的小折叠。
- 美化：@import 的网址里有分号（字体链接常有）时以前会把整份美化弄坏；注释里关掉的 @import 以前会被打开。都修好了。停用兔子镜时美化也一起拿掉。
- 生图标签整理：标签写法时两个人都有的外貌（比如都是长发），以前第二个人的会被当成重复删掉；自然语言的画面描述有时会被当成标签打乱顺序；「1 girl's hand」这种所有格会被拆开；跨逗号的权重组会被拆散。都修好了，只理真正的标签行。
- 两套开关：切换生成方式时，如果两边材质纹理开关不同，聊天里已经显示的画面现在也会跟着铺上或撤掉。关掉「各记一套」再打开时，两边都从现在的开关起步，不再翻出以前记的。
- 单选改名同步样式：也认大写的 NAME=、写在引号后面不带空格的 i 标记。

## 1.68.86 导入美化

- 设置 →「主题与外观」新加「导入美化」：粘贴一段 CSS，或从 .css 文件导入，就能改兔子镜的设置界面、工具弹窗（维修兔、挨打猫、重说等）和外置框（包括外置标题框），比如给框外加装饰、给标题框换底色。可以随时关掉（内容留着）、导出给别人、清空。
- 只是一段样式：不跑脚本、不进提示词、不改兔子镜画面里面模型写的内容。和配色一样，只保存在这台设备上。
- 「美化能用的名字」里列了设置界面、工具弹窗、外置框、外置标题框、标题文字、标题旁兔子按钮这几处的写法，兔子镜以后不改这些名字，美化更新后也不会失效；「插入可用的名字」会把它们按格式填进文本框。
- 写了 !important 的美化一定盖得过兔子镜自己的样式（美化另放一份在单独的层里）。写在元素自己 style 里的 !important 仍然盖不过。

## 1.68.85 材质：光泽

- 查了视觉研究：人认一个东西是什么材料，主要靠表面的高光，颗粒是次要的。兔子镜以前的纹理只会做哑光（从左上打光照出凹凸，没有高光），所以不管写什么材料，铺出来都差不多。
- 纹理描述再加一个光泽词：data-rm-texture="材料 粗细 方向 形状 浓淡 光泽"，光泽写哑光／半光／亮面。规则多 17 个字。
- 哑光：和以前一样，不画高光。半光：左上一片柔的亮区。亮面：一条边缘清楚的亮带，加一点反光。高光颜色从它自己的底色调亮；深色上比浅色上明显（研究结论）；亮带的角度、起点、宽窄按这块东西的大小和这一面的种子变，两块东西不一样。高光会压到文字、让字看不清时自动减弱，减不下去就不画。
- 哑光的纤维质感：边缘不再是一条硬线，用它自己的底色往外描一圈、把边搅软，看起来是软的东西。被裁掉的（overflow hidden）不做。
- 浅底上的纹理力度从六成调回四成，长条纹调到三成（1.68.81 调重以后，浅色面上的条纹像划痕）。纤维的簇更大、更软一些。

## 1.68.84 内置生图：交给生图前把标签理一遍

- 规则里本来就要求标签开头先写人数和性别（1boy, 1girl），模型大多照做，但偶尔写坏：比如写成「1boy, 1girl piggyback」，1girl 和动作粘成一个词，生图模型就认不出画面里有个女孩。
- 现在交给柏宝绘／智绘姬之前，兔子镜自己把标签理一遍：粘在一起的拆开；1boy、1girl、2girls 这类人数标签挪到最前面；「1 girl」写成「1girl」；重复的去掉。人物的角色栏标签也理。
- 只理英文标签：中文画面描述、英文长句的自然语言描述、带权重的写法（1.2::xxx::、{xxx}）都不动。没有加规则，注入一个字没变。

## 1.68.83 内置生图：每个人都有角色栏，画面收近一点

- 对比了好看和难看的几张图（质量词、画师、负面完全一样，差别全在兔子镜写的那几段）：难看的那张画面里塞了三个人加柜台、算盘、飞舞的算珠，还是全景；背上的女子只写成「女子」，没有自己的角色栏，画出来是随机路人。好看的两张都是两个人、近景、一个动作，每人都有角色栏。
- 现在生图规则里写明：画面里的每个人各写一条外貌（用正文里的名字，不写成「女子」「少年」）；一幕两人以内、近景或中景为主。开了生图 LLM 时，它规划画面也照这两条。
- 注入多了约 40 字（只在开了内置生图时）。宽阔的大场面会少一些，换来出图更稳。

## 1.68.82 跟随和独立各记一套开关

- 「生成方式」里新加一个开关：跟随和独立各记一套开关。打开后，切换「跟随当前 API」和「使用独立 API」时，面数、抽签方式、规则强度、创意扩展、视觉场景、色调、用户指令优先、世界观锁、视觉提示词注入开关、内置生图和提示词格式、材质纹理、额外资料读取这些开关，会换成那一边上次记住的值。比如跟随主 API 时只开一面、不开生图，独立 API 时三面全开。
- 打开时两边都从现在的开关起步；关掉就合回现在这一套。视觉提示词、文风这类文字框两边共用，不分。
- 注入量本身没怎么变：什么都不勾、一面，跟随模式现在约 6100 字（估算 4000 token 出头），1.67.95 时约 5800 字；变多的主要是开了内置生图那一段（同人卡按原作画、图框照自己的位置画，多了约 650 字）。

## 1.68.81 材质：看得见、先想材料、描一道厚度

- 纹理力度提上来。以前压得很轻（怕铺重了千篇一律），结果是看不见；现在柔光和浅底的正片叠底都提到能看见的程度。
- 纹理描述前面加一个材料名：data-rm-texture="材料 粗细 方向 形状 浓淡"，材料是它在现实里是什么做的，模型自己写、不给列表。兔子镜不查表、画纹理也不看它，只用来记「近几面用过什么材料，这一面换一种」。目的是逼模型设计前先决定材料，不只是填表。规则总共多 8 个字。
- 厚度：在铺了纹理的那块和铺过去的板子上，用它自己的底色描一道受光的亮边（左上）和一道背光的暗边（右下），粗细按它的大小算，两块底色不同的东西描出来不一样。不加投影、不加整面的光（试过，一加就是通用网页卡片）。模型自己写了 inset 亮暗边的，兔子镜让开。

## 1.68.80 选项点了没反应、纹理看不出来

- 单选按钮会被兔子镜改名（加上这一面自己的前缀，免得和别的面串）。以前只把编号同步进了样式，名字没同步：模型在样式里写「选了 name=发型 的某一项就换头发」，改名后这条永远对不上，捏脸这类面怎么点都不变样，维修兔也修不好。现在改名时样式里写的名字一起改。
- 纹理写在整面底板上、底板又被几块自己有底色的卡片盖住大半时，纹理只能从缝里露出一点。现在同一种纹理也铺到这几块大卡片上（铺在卡片内容下面，不盖字和图）；小按钮、图片、画出来的图不铺；卡片里有会弹出去的小框时不铺那一块，免得弹出的东西被压住。这一面还收着时，等展开后再铺。
- 判断「底色很浅」时也看渐变的颜色了（以前只看纯色，浅色渐变底按深底处理，纹理更淡）。

## 1.68.79 「两种交互」改成「第二步接在第一步的结果上」

- 规则里原来四处写着「每面／每条至少两种不同的交互（如按住＋切换、刮开＋翻页、拖动＋点亮）」，模型容易把它理解成「凑够两种方式」，最省事的凑法就是一个主要动作再加几个点开看字的小框。
- 现在改成：一个主要动作贯穿，第二个动作要在第一个动作造成的新状态里才能做，改变物件本身，不另开小框补内容。和原来那句「至少走两步，后一步建立在前一步的结果上」合成一句；去掉了「按住＋切换」这类方式相加的例子，也没放具体场景的例子，免得被照抄。
- 记录格式里的交互方式列表保留（兔子镜靠它记最近用过什么、提醒换口味），例子换成不带具体动作的占位。总共多 10 个字。

## 1.68.78 交互不再老是「切换按钮＋点开小框」

- 写法清单：兔子镜每面给模型三种现成交互写法，以前「开关切换」和「弹窗」常常一起出现，模型就凑成「一个切换按钮＋几个点开的小框」。现在一份清单里不同时给这两种；最近两面里有一面实际用过其中一种，这一面两种都不给，换成拖、按住、旋钮、刮开、累积这类。（以前「弹窗」被算成丰富的交互，这一对从来不会触发换口味。）
- 方案 2 的说法：从「整个媒介一起切换状态」改成「用媒介本身的动作（拉、拧、翻、拨、拖）让整体换一种状态，不用单独的切换按钮或点开的小框，变化直接落在画面和物件上」。依据是交互设计里的「直接操作」原则：结果要出现在被操作的东西身上；以及「少用弹窗」：弹窗会挡住原画面，不适合放正文。多 34 字。
- 和 1.68.77 的「最近两面用过方案 2 就不再指定」一起作用。

## 1.68.77 两个场景切换后全空白、浅底纹理看不见、交互总是「切换＋弹出」

- 修复坏兔子镜：模型给两个场景各写死了内联显示（一个显示、一个隐藏），再用「开着时藏 A」「没开时藏 B」两条样式切换。以前兔子镜只会照新生效的规则把 A 藏起来，却不会在「藏 B」那条规则失效时把 B 放出来，点一下切换后两个场景都不见了。现在内联值和规则写的一样时，规则失效就暂时拿掉这份内联，规则回来再放回；「:not(开着)」这种写法也认得了。旧的兔子镜也生效。
- 材质纹理在很浅的底色（接近白）上以前几乎看不见：叠加方式在浅色上没效果。现在浅底改用只压暗面的方式，力度调到约三成，看得出纸面起伏又不盖字。
- 交互单调：大多数形式只在方案 1、2 之间各一半地抽，方案 2（整个媒介一起切换）几乎都被做成「一个切换按钮＋几个点开的小弹层」。现在兔子镜记下每面实际实现的方案，最近两面用过方案 2 时，这一面不再指定它。

## 1.68.76 读得舒服：显示时自动修几项小毛病

- 兔子镜显示出来后，自己量几项常见的小毛病并当场修，不调用模型、不加规则、不花字数，旧的兔子镜也生效：
  - 中文排版：打开浏览器自带的中文断行规则（标点不放行首），中英文之间自动留一点空（浏览器支持时）。
  - 手机上正文小于 12 像素的放大到 12 像素（一两个字的图标、角标不动）。
  - 一段较长的中文行距低于 1.45 倍的，放到 1.6 倍。
  - 有底色的块里文字左右几乎没留白的，补一点内边距。
  - 小于 28 像素的按钮和可点的小圆点，只把「能按到的范围」往外扩一点，样子不变。
- 每一项改完都量一遍：撑破了原来的框、被裁掉、短标签多折出一行或把同一排的东西挤得折行，就撤回这一项，保持模型原来的样子。兔子镜自己的标题栏和按钮不碰。

## 1.68.75 材质纹理规则终于发出去了；「按住」外层状态类接线

- 修复：材质纹理（实验性）开关从 1.68.65 起其实一直没生效。兔子镜生成提示词时只抄一份「名单上的设置」，这个开关漏在名单外，抄过去永远是关的，所以不管用哪个模型，规则都没发出去，诊断里一直是「本面写了=0 处」。现在补进名单，并加了测试：开关打开时规则一定在提示词里。
- 「按住」接线：模型常用一个外层状态类写按住效果（比如按住看素颜：.素颜 .口红{透明}），原本靠脚本在按住时加上这个类，脚本被拿掉后按住没反应。现在兔子镜会找出这样的类（只在 CSS 里当外层用、页面上没有任何元素带着、管的东西就在按住区域里，而且只有唯一一个），按住时加到按住区域上，松开撤掉。旧的兔子镜也生效。

## 1.68.74 材质纹理：有光照的真实凹凸

- 材质纹理（实验性）换了做法：以前是一层平的明暗颗粒，像印上去的；现在把颗粒当成表面的高低起伏，从左上打光，纸面有起伏、皮面有颗粒、木头有纹路、石墙像墙。毛毡、绒布这类软的先揉软再打光，不会像揉皱的塑料。
- 东西的边缘和转角多一圈很淡的暗影，左上边缘一点亮，看起来有厚度、不像贴纸；按元素大小算，小按钮不会整块变暗。
- 两层大小不同的纹理叠在一起，大面积时看不出是一块块重复拼的；纹理拼接处没有接缝。深色底不再被刷灰。
- 材质那条规则写明「整面光从左上来」，模型画的阴影和纹理的凹凸方向一致。字数和原来一样。
- 「斜」方向的纹理按横向处理（打了光的纹理一旋转就会出接缝，光的方向也会跟着歪）。仍然不放任何图片，都是浏览器当场算的。

## 1.68.73 第二轮复查修正

- 去掉本体外那圈底色：隔着透明包装找到的本体，只有外层和它是同一色调、只差深浅时才去掉外层。手机的黑边框、相框的木框是本体自己的外壳，不再被剥掉；半透明的玻璃卡（靠外面深底才看得清字）外层也不动。
- 按下手感：点在按钮最边上时，按钮沉下去、缩一点后指针可能已经不在它身上，以前松手会点不到；现在按住期间会「抓住」它，只要还在原来的范围里松手就照样算点击，拖出去再松手和平常一样不算。
- 按下手感：默认是行内的标签包住整面时，以前会整面变淡，现在不加；用键盘按下、点击把按钮藏起来时，不会一直停在按下的样子；oklch 这类读不准的阴影颜色改用平按钮的手感。
- 母本库：刚删的库编号会记在本机，刷新页面也不丢；下次保存时一定从酒馆备份里去掉，没存上之前不自动恢复，手动恢复也不会把它补回来。
- 母本库：自动恢复只在「本机记录也一起没了」或「上次存备份时本机明明有库」时进行。上次存的时候本机就是空的（自己删光，或备份里是别的设备的库）改成先问。
- 材质纹理开关关掉时，当时为纹理加的定位和变量也一起撤掉。

## 1.68.72 按下手感和去外圈的复查修正

- 电脑上按住按钮、鼠标从按钮里的字挪到按钮边上，以前会被当成松手；现在只有移出按钮本身才松开。手机上手指一滑（在滚动）照旧立刻松开。
- 模型自己给被点的东西写了动画（比如翻牌 0.6 秒）时，松手不再套兔子镜的回弹，免得把它的翻面压快。
- 模型把整面内容包进一个可点的标签时，不再「点哪里整面都变暗」：很大的元素不加按下效果。
- 去掉本体外那圈底色：一面收着、量不出里面高度时（老的 iPhone 浏览器），打开后再检查一次。

## 1.68.71 按下手感、光源统一、纹理调淡

- 按下手感：模型画了看起来能按的东西，却常常没写「按下去」的样子。现在兔子镜按它的外观补一个对得上的按下反馈，只在按住的那一下出现，松手就回去：凸起的按键往下沉、阴影收短；平的按钮轻轻缩一点、暗一点；小圆钮缩得多一点；纯文字只淡一下。手机、TT、电脑和键盘（回车、空格）都一样，旧的兔子镜也有。
- 不碰：模型自己写了按下样式的、禁用的、兔子镜自己的按钮和标题栏；本身歪着摆的只变暗不位移；整面都设成可点的大底板不算；手指一滑（在滚动）就松开；系统开了「减少动态效果」时只变暗。
- 材质那条规则里去掉了四个材质举例，换成「整面只有一个光源方向，物件的高光、渐变和阴影都朝同一边」，字数还少了几个。
- 材质纹理（实验性）整体调淡到原来的六成左右，「明显」那档不再发脏。

## 1.68.70 去掉本体外那圈底色：改回用清洗器，规则还原

- 兔子镜本来就有一个清洗器：标题下面第一层如果只是一块有底色、有内边距的垫底面板，里面只装着真正的本体，就在显示时去掉这层的底色、内边距和阴影（不改聊天记录，旧的兔子镜也生效）。
- 它以前只认「面板里直接就是本体」。模型常在中间多套一层透明的限宽 div（比如「破庙神龛螺钿暗匣」那面），清洗器就认不出、跳过了，所以那圈底色又出现。现在往里多看最多两层：中间隔着透明包装、里面那件有底色的占了大部分高度（其余只是隐藏开关或一两行说明），也会去掉外圈。
- 信纸（纸面里直接是几段文字）、并排的几张卡片、动态场景照旧不动。
- 1.68.69 加进规则里的那几句撤回，规则文字回到 1.68.68 的样子，不多占字数。

## 1.68.69 标题下面直接是本体，去掉框外那一圈底色

- 以前模型常在本体（匣子、信纸、手机……）外面再包一层只用来垫底的面板：单独铺一块底色、留一圈内边距、加阴影，看起来像「框外还有一圈粉色」。现在规则写明：标题下面直接是本体本身，不再包这层衬底；本体宽度和标题栏对齐，不缩成居中的窄条。
- 原来就有「不在本体外加与媒介无关的框（比如黑色边框）」这一条，这次是在同一条里补上「衬底面板也算」，没有另加新规则。
- 规则里说的「主背景」改为指本体自己最外层的底色。柔和浅色的三层深浅跟着往里挪一层：本体自己的底色是背景那一档，里面放内容的那层是承载面，物件和按钮是主体那一档。
- 只影响之后新生成的兔子镜，已经生成的不会变。场景类的形式（风景、房间、动态画面）场景本身就是本体，不受影响。

## 1.68.68 材质纹理规则去掉材质举例

- 1.68.67 的规则里列了「纸、布、木、毛绒、石、金属、屏幕玻璃」做例子，模型容易只在这几种里挑，变成固定几样。现在去掉举例，只说「写在这一面最像实物的主体或承载面上，质感从它在现实里是什么做的推出来」。
- 粗细、方向、形状、浓淡这四组词保留：它们是告诉兔子镜怎么画纹理的写法，不是材质名，任何材质都用这四组词描述。

## 1.68.67 材质纹理打开后每面都会用

- 以前「材质纹理（实验性）」打开后，规则写的是「可以写」，模型几乎都选择不写。现在改成：开关打开时，每个 HTML 面都在一个元素上写一处质感描述。
- 写在这一面最像实物的主体或承载面上，质感从它在现实里是什么做的推出来；一面只写一处，不写在整面最外层背景上；近几面用过的会提醒换一种。
- 规则比原来还短一点（约 210 字）。开关关着时照旧一个字都不发。
- 全链路诊断的「VS 交互方案记录」下面多一行「材质纹理」：开关开没开、这一面模型写了几处、写的什么、实际铺上了几处，方便看模型有没有照做。

## 1.68.66 母本库被清空后自动恢复

- 有的宿主（比如部分 TT）重开时会清掉网页里存的数据，母本库就跟着空了。以前要每次手动点「恢复」；现在开着母本库抽签时，兔子镜启动后会自己检查：本机母本库空了、酒馆里有备份，就直接补回来，并弹一句「已自动从酒馆备份恢复 N 本、N 条」。
- 只补本机没有的库，本机已有的不动；抽签总开关不改。
- 两种情况仍然先问再恢复，免得把你刚删掉的库又补回来：上次存酒馆备份失败过；或者你刚在本机删了库、还没来得及存进备份。
- 启动后检查的时间从 15 秒提前到 6 秒，尽量赶在第一次生成之前恢复好。

## 1.68.65 材质纹理（实验性，默认关闭）

- 设置 →「动态场景与绘制细节」里新增「材质纹理（实验性）」，默认关闭。打开后，模型可以给画面里的某一个实物（纸、布、毛绒、木头、石头、皮革……）写一句质感描述：粗细、方向、形状、浓淡，兔子镜照着现场生成一层很淡的纹理，叠在它自己的颜色上、文字下面。
- 不放任何图片：纹理是浏览器按几个数字算出来的，颜色仍是模型写的底色，所以浅色、深色、莫兰迪都能用；每一面的纹理细节也都不一样。
- 防模板化：材质从这一面的形式本身推出来，一面最多一处，不用在整面背景、屏幕和界面上；兔子镜会记住近几面用过的质感，提醒下一面换一种或不加。
- 开着时每次请求多大约 230 字的规则；关掉后不再发，聊天里已经铺上的纹理也会一起撤掉。快拍的镜片和收藏夹里同样能看到。

## 1.68.64 复核后的三处小修

- 快拍：同一层的重说版本记在三个地方（本机、聊天文件、版本存档），换过设备时它们可能不一致；现在取最后改过的那一份，「第几版」和当前显示的那一版对得上。
- 快拍：正在打开时停用兔子镜，读完数据后不会再自己弹出来；旧的一份兔子镜停用时，不会关掉新装那份打开的快拍。
- 内置生图：读图地址的去重筛选被一句注释吞掉了，读不到时会多试几个空地址和重复地址；现在只试有效的地址。

## 1.68.63 快拍：列出重说的每一版、镜片里能看到图、可以直接跳页

- 重说过的楼，快拍会把这一面存下的每一版（最多 5 版）都列出来，紧跟在当前那一版后面，标着「第几版」。多面的楼按面分别列。
- 镜片（缩略图）里以前看不到画好的图，只有一个灰框写着「这一面的画面」：缩略图的小窗口读图时没带上酒馆的登录信息。现在能带上（里面仍然不运行任何脚本），第一个地址读不到也会换地址再试。
- 翻页：中间加了页码，可以直接选第几页，不用一页页点「更早」「更新」。

## 1.68.62 手机设置弹窗两处小问题

- 手机上点弹窗外面关闭时，会连着关两次（没有坏处，但多做了一次）；现在只关一次。
- 电脑上把窗口拉窄打开设置、再拉宽时，三个设置弹窗的样式会掉；现在只要弹窗已经换成手机样式，就一直保持。

## 1.68.61 快拍和 /兔子镜 的几处问题

- 快拍：普通回复里只要出现「生成失败」「面未完成」这几个字，就会被当成失败的兔子镜列进来；现在只认兔子镜自己的失败标记。
- 快拍：「跳回原楼」的闪烁以前不会播，标记还留在楼层上，下次打开快拍时那一层才闪；现在跳回去当场闪一下，之后自动清掉。
- 快拍：往前加载旧楼层时按酒馆真正监听的方式点「显示更多」，不再白等；等待期间重新打开的快拍不会被上一次跳转关掉。转屏或改窗口宽度后，镜片缩略图按新宽度重算，不被裁掉。兔子镜停用或更新时，开着的快拍一起关掉。
- /兔子镜：名字或别名已被别的插件占用时不再覆盖；停用旧的一份兔子镜时，不会删掉新装那份登记的命令。

## 1.68.60 被模型内容审核截断时说清楚

- 副 API 写到一半被服务商的内容审核掐断（finish_reason 是 content_filter / safety）时，以前只报「不是完整兔子镜」，像是兔子镜坏了。现在直接说明是模型的审核截断，同一组签再试多半还会被拦，建议「🔄 重说」换一组签或换限制更少的模型。

## 1.68.59 新增七个同人奇病梗

- 主题元素「荒诞/超现实」里新增：宝石病 / 宝石失明症、飞鸟症、星屑症、透明症、鳞片症 / 人鱼化、融雪症、灵魂伴侣 AU。和花吐症一样，都是把说不出口的感情变成看得见的东西，适合画面和生图。

## 1.68.58 材质要求压短

- 材质那条从八个例子压到四个，免得模型照着例子套。现在写的是：材质从这个形式和画面里的主要物件在现实里是什么做的推出来（比如纸的纤维折痕、玻璃的透光反光、毛绒玩具的绒毛边、屏幕的像素），只做在主体、物件和承载面上，小面积、轻量，不铺满背景，不是每面都同一种效果。画面里有毛绒小熊这类东西时，也会按它自己的材质来画。

## 1.68.57 柔和浅色分出三层；材质跟着展现形式走

- 柔和浅色模式以前要求「背景和承载面都用浅色」，画面常浅成一大片。现在明确分三层：背景取风格里中等偏浅的颜色，承载面（纸、卡片、屏幕）更浅、像同色调的白，主体和能点的部件比背景深一到两档。8 种风格、87 个颜色和每面指定主色族都不变。
- 材质要求更具体：从这个形式在现实里用什么做成推出来（纸的纤维折痕、布的织纹走线、木纹、玻璃透光、金属冷光、陶瓷釉面、毛毡绒边、屏幕的玻璃和像素……只是举例），做在主体和承载面上，小面积、轻量，不铺满背景，也不是每面都套同一种滤镜。

## 1.68.56 撤回 1.68.52–1.68.55 的浅色配色改动

- 那几版改的是一张旧的配色参考表，现在生成时已经不用它（颜色由模型按色调模式自己定），所以改了没有效果，现已原样撤回。
- 1.68.54 里「累积改变」阶段显示的修复和小兔子菜单图标统一保留。

## 1.68.55 浅色改成莫兰迪灰调

- 浅色配色整体压灰：背景、主体、按钮和点缀都带一点同色调的灰（粉配紫雾灰、蓝配蓝石灰、绿配青灰……），不再是偏鲜的粉嫩色。
- 层次靠深浅：背景是灰调浅色，卡片是近白纸面，主体比背景深一截。深色配色不变；258 组浅色配色的文字都清楚可读。

## 1.68.54 累积改变的阶段能显示了；小兔子菜单图标统一；浅色回到原来的背景

- 「累积改变」类的面（播种→发芽→开花、一格格点亮这种）有时一个阶段都不显示，点按钮也不变。原因是画面按「现在是第几步」来显示对应阶段，兔子镜以前只记了数、没把这个数标出来。现在会标出来，已经生成的旧面重新打开也能用。
- 小兔子菜单的图标统一成一套：🔄 重说、✍️ 续写、🖼️ 生图、📷 快拍、📖 收藏夹、🎨 配色、🔍 文字对比、✖️ 关闭。提示文字里的「重说」也跟着换。
- 浅色配色的背景回到以前那种浅色。层次靠卡片更白、主体比以前深一档来拉开；陪衬色仍只用在按钮和小点缀上。

## 1.68.53 浅色层次改成同色调

- 1.68.52 把主体换成了陪衬色，撞色太突兀。现在主体回到主色系、只是比背景深一截；卡片用同色调的浅灰纸面；陪衬色只留给按钮、点缀这类小地方。
- 背景仍比以前深两档，三层照样分得开，258 组浅色配色的文字都清楚可读。

## 1.68.52 浅色画面分出层次

- 浅色配色以前背景、卡片、主体都取得很浅，看起来是「一大片浅底」。现在背景深两档、卡片是近白纸面、主体换成陪衬色，三层一眼分得开，主体和背景也不再是同一个颜色。
- 仍然是柔和色，深色配色不变。258 组浅色配色的文字都保持清楚可读。

## 1.68.51 快拍里能看到已经画好的内置生图

- 快拍挂镜时带上和原楼相同的聊天、楼层和 swipe，已经存在本机的内置生图会放回图框，不会重新生图。
- 镜片缩略图在放进页面之前先把这些图填进画面。整页和点进去看的那一面同样能看到。
- 电脑、手机和 TT 上这次没有代跑生图。没有存档的图框仍是空的。

## 1.68.50 勾选切换修复收进勾选救援

- 模型用「勾选框后面紧挨两个 class」做标签页、折叠或翻牌时，作用域加上去有时会点了没反应。替代样式仍是单独补一小段，不和维修兔的「点了没有反应」合成一套。
- 仍是主体加载之后、第一次点兔子镜面过 700 毫秒才开始看，启动时只扫最后 8 个楼层。
- 电脑、手机和 TT 上这次没有代点那些勾选面。

## 1.68.49 打开后的画面记进防重复

- 展开兔子镜、或独立 API 那一面变成就绪时，仍会等画面画出来，再把亮暗、配色和交互种类记进防重复，让下一次生成避开刚用过的样子。
- 记录仍是主体加载之后、第一次点兔子镜面过 700 毫秒才开始，不是一开机就记。同一面反复收起展开不会反复记。
- 电脑、手机和 TT 上这次没有代跑生成。打开头像的聊天里，展开后头像应还在、不重复。

## 1.68.48 手机上的设置弹窗收进主界面

- 手机或触屏（含 TT）上，高级设置、世界书设置、正文标签管理仍会换成最上层的全屏弹窗。返回键、Esc 和点背景还是通过各自的关闭按钮关掉。
- 换成全屏弹窗发生在绑定点击之前，所以原来绑在弹窗上的关闭不会丢。电脑宽屏保持原来的弹窗，不升成 dialog。
- 不再把设置水印改成旧版本号。电脑、手机和 TT 上这三个弹窗有没有被裁切。

## 1.68.47 连接配置下拉框收进设置

- 「连接配置」这一行现在就在独立 API 的连接卡片里，打开设置就能看到，不用先去点别的地方才插出来。
- 选项在设置挂上时填一次，再进入连接页时刷新。选配置后保存的仍是 profile ID 和模型，不复制酒馆密钥。
- 不再把设置水印改成旧版本号。电脑、手机和 TT 上这一行会不会撑破卡片。

## 1.68.46 维修兔推荐收进主模块

- 悬停维修兔时补上的「推荐使用」写进维修兔状态和菜单本身，不再单独挂一个全页监听。按钮提示、菜单里的推荐、修完后跟着变或消失，这些表现保持原样。
- 旧楼层刷新后仍会走维修兔状态写入，推荐会重新出现。电脑、手机和 TT 上菜单是否被裁切。

## 1.68.45 装了鸡尾酒后 /兔子镜 打不开

- 鸡尾酒+会推迟扩展加载，还可能让聊天输入和 `getContext()` 用到两份斜杠命令解析器。以前 `/兔子镜` 只登记在其中一份上，输入框执行时酒馆报 `Unknown command at position 1: "/兔子镜"`，设置打不开。
- 现在会向真正执行输入的那份解析器登记，并在主界面就绪后再补登记几次。名字被别的插件占着时仍然不覆盖。

## 1.68.44 划到别的版本时缺壳卡马上出；测试架子整体跟上代码

- 最后一条回复划到另一个版本、而那一版没有兔子镜时，缺壳卡（「暂未找到与这条回复对应的已保存兔子镜」）以前要等这个聊天上一次生成过去 3 分钟才出来。现在只有正在等兔子镜的那一版才等，划到别的版本立刻挂卡。
- 138 个一直失败的测试全部理清：93 个是测试没跟上代码拆分，45 个是测的旧行为（顺序轮播已取消、重说默认重新抽一张、1.67.80/1.67.93 的规则等）。没有发现真 bug。顺序轮播的测试换成了「取消得干净」的测试；配额压缩改成「没备份的一个都不丢」。现在 634 个测试全部通过。
- 两处代码小整理：markup.js 一处过时注释（fixed 先改写成 absolute）；faceDrawCatalog 的 listLibraries 单独传也生效。
- 删掉三个没有任何地方引用的文件：ttSettingsEntry.js、independentQualityGate.js、performanceDiagnostics.js（性能诊断那个全局钩子从来没被装上过，读它的地方都是可选链，保持不变）。

## 1.68.43 「装了不显示」自检补漏：四种以前完全没提示的情况

- 安装文件不完整、新旧版本文件混在一起、文件有语法错时，整组启动文件在任何代码运行前就作废。酒馆把它当作加载成功，启动自检也跑不起来——以前这种情况魔法棒里没有兔子镜、/兔子镜 也没有、什么提示都没有。现在 style.css 里有一条兜底规则（样式是酒馆单独加载的）：脚本没跑起来时，魔法棒菜单和扩展面板里会显示「兔子镜没有启动：安装文件不完整……」。在浏览器里实测过：缺导出时酒馆确实不报错、入口和命令都没有，只有这句话能看到。
- 页面里已有别处的兔子镜启动桩（别的文件夹、别的版本）时这一份会让位。以前让位是悄悄的，现在弹提示说明是哪种情况，让位后点入口、打 /兔子镜 也会说明，不再没反应。
- 页面上一直没有魔法棒菜单（被美化或别的插件换掉）时，以前入口和设置界面都悄悄放弃；现在等 20 秒后提示。
- 页面上登记的兔子镜版本被另一份改掉导致设置界面没挂上，以前不出声；现在报出页面上登记的是哪个版本。/兔子镜 没登记上（被同名命令覆盖）时如实返回，提示里不再教用户打它。

## 1.68.42 多面计划失败时说出真正原因，不再只报「具体原因尚未确认」

- 「每一面怎么呈现」里某一面没选任何条目、常驻条目被禁用或拉黑、可追加条目不够、常驻条目超过 16 项，以及世界书抽签没选条目、逐面轮播进度读不到，这几种失败以前经外部库准备链路一包装，全都显示成「本轮计划校验未通过，具体原因尚未确认。诊断原因：BATCH_PLAN_INVALID」。现在各报各的原因，并标明是第几面。提示里只带面号，不带条目名和正文。

## 1.68.41 正文为空提示：认出「正文被画进读不到的内嵌页面」

- 有的美化把正文原文藏起来，改画进内嵌页面（前端卡、酒馆助手界面）；内嵌页面不让外面读字时，兔子镜读不到正文。以前这种情况会被说成「文字还没显示完」，现在直接说是被画进了读不到的内嵌页面，以及怎么办。能读的内嵌页面照旧会读。

## 1.68.40 正文读出来为空时说清楚原因

- 换预设后常见「当前正文在可见性检查和标签过滤后为空」，以前只让你「调整过滤标签或确认正文已完成渲染」，看不出是哪一种。现在直接说是哪种情况：
  - 跳过的标签把整段正文包住了：会写出是哪个标签。如果这一层里这个标签只有开头没有结尾（预设漏写结束标签，或开闭标签拼写不一样，比如 `<UpdateVarible>` 配 `</UpdateVariable>`），会说明后面的正文都被算进了这个标签，叫你先取消勾选它。
  - 美化把字藏了（逐字显示、淡入动画还没放完，或样式把正文设成不可见）。
  - 这一层没显示在页面上（被收起、还没滚到、被别的插件换掉），或者正文画进了读不到的内嵌页面。
- 只改提示文字，判断正文、过滤标签的规则没变。

## 1.68.39 内置生图：照图框在这一面里的内容画

- 一条回复出好几面、每面都有图时，几张图常常全是正文最新那段情节的动作。原因是写图框画面时照着正文最新一段写，而不是照这一面里这个图框代表的东西写。
- 现在图框画的是它在这一面里所在位置的那样东西：这张照片、这张牌、这一页、这一格旁边写的标题、说明、时间点和场面。正文只用来补人物外貌、当时衣着和地点；正文最新一段的情节不是图框内容，除非这一面写的就是那一刻。不限定画什么动作——在盗墓就画盗墓，翻相册就画那张照片里的事。同一面几个图框各画各自位置的内容，几面之间也不画成同一个场面。
- 开了生图 LLM 时：把图框前后紧挨着的文字（标题、说明、时间点，最多 300 字）一起交给它，照这个画；同一条回复里几面的画面规划按顺序来，后面的面看得到前面已定下的画面，不画成同一个场面。只排规划，出图照样一起出；某一面规划失败不挡后面的面。

## 1.68.37 设置里的勾选框和文字回到同一行

- 设置面板里所有带勾选框的选项（比如「启用镜面生图」「启用挨打猫」）以前在酒馆主题下会变成勾选框单独一行、文字掉到下一行，看起来像「只有框框没有字」。现在勾选框和文字并排，文字太长就在右边自动换行。
- 37 个设置页在手机竖屏（320、390 宽）、手机横屏和电脑宽屏下逐页检查：勾选框没有再和文字分行的，也没有超出窗口被剪掉的内容。

## 1.68.36 启动自检；/兔子镜 命令

- 兔子镜启动时每一步单独保护：某一步出错不再整个静悄悄消失，而是弹提示「第几步没成功」，带「复制诊断」。后面的步骤照样跑，魔法棒入口照样装上。
- 报错经过了别的插件的代码时，提示里直接写「可能和『某某插件』冲突」，建议先在「管理扩展」里暂时关掉它再看。文件没下载下来（网络不稳、更新后没刷新）会直接说刷新再试。别的情况请复制诊断发给作者。点入口或打命令时打不开，提示标题是「兔子镜打不开」。
- 魔法棒里的兔子镜入口被别的插件的样式或脚本藏起来时，弹提示说是谁藏的（能认出来的话；写在自定义 CSS/美化主题里的也会说明），带「打开兔子镜设置」。如果是你自己关掉的，点「不再提醒」。入口只是被挪进别的插件的分组、或者分组折叠着，不算藏起来，不提示。
- 同时开着两份兔子镜（比如正式版和测试版）时提示只留一份。
- 新命令：在聊天输入框打 `/兔子镜`（或 `/rabbitmirror`）回车，直接打开兔子镜设置。魔法棒入口找不到时用。
- 诊断里有：兔子镜版本、启动步骤、报错信息和位置（去掉了网址主机，引号里的片段遮掉）、加载了哪些扩展的文件夹名、浏览器型号和窗口大小、时间。不含聊天和设置内容。手机上复制不了时会把诊断摆在提示里，长按全选自己复制。查出问题才弹，正常时什么都不显示。
- 兔子镜完全没被酒馆加载时（没装上、被禁用、酒馆版本低于 1.13.0），兔子镜自己的代码一行都不会跑，这些提示也不会出现；这时请看酒馆「扩展 → 管理扩展」：列表里有没有兔子镜、有没有勾上、窗口顶上有没有红字。

## 1.68.35 样本箱复查修正

- 隐私补漏：渲染骨架里维修兔实测留下的那条记录（带没反应控件的按钮文字）现在也打码；结论里控件名本身带「」的不再漏字；方言识别里认不出的中文键改成只留长度。导出文件里仍然一个字的正文都没有。
- 点过维修动作后的结果面板，不再残留三行分组标题。
- 「点了没有反应」修完只记真的没修上的（没命中任何路线、或副本复核明确失败）；「修了但还没验证」不记，免得把样本箱灌满。
- 拿不到源代码的面不再互相覆盖；本机空间不够时样本箱最先让路；巡逻结论只在真的记上了才写「已记进样本箱」。

## 1.68.34 待修样本箱；维修兔菜单分组

- 维修兔巡逻实测有控件没反应、或「点了没有反应」修完仍没好时，自动把这一面的写法骨架记进本机的「待修样本箱」（文字全是占位，不含聊天内容）。设置 → 工具 → 缺壳扫描下面可以「导出待修样本箱」一次导出全部、也可以清空。同一面只记一份；最多留 40 面、总量约 2 MB，超了挤掉最早的。只存本机，不会自动发出去。
- 这是给作者攒样本用的：新模型（比如 Gemini 4）写出来的新写法，攒十几面一批加进方言表和修复器，比一面一面截图快。
- 维修兔菜单按用途分三组：「不确定哪里坏了」（自动判断、只巡逻）、「按症状修」（点了没反应、文字被裁、手机排版、整面压窄、空白或代码、样子不对、全部试一遍）、「撤回与导出」（恢复到初始、全链路诊断、复制／下载 HTML）。按钮的功能一个没变，只是重新排了顺序、改了几个说法。

## 1.68.33 母本库被清空时，提示里直接能恢复

- 宿主（比如 TT）更新或重载时把网页里存的数据清掉，母本库就空了。以前启动后弹提示「点这里去恢复」，点了只是打开设置跳到母本库页，恢复按钮藏在页面最底下或「换设备」弹窗里，很难找到。
- 现在提示里直接有「恢复」按钮：点一下就从酒馆备份恢复，只补本机没有的库，已有的不动，抽签总开关不改；恢复完在提示里写明补回了几本几条。旁边的「去母本库看看」照旧打开母本库页，那一页正开着的话会跟着刷新。
- 不会自动恢复，一定是你点了才恢复。

## 1.68.32 柏宝绘的图不再另存一份

- 1.68.29 让柏宝绘返回的别处链接也下载进酒馆，但柏宝绘自己本来就把图存进它的图库，这样会存两份、多占空间。改回来：用柏宝绘时只记它给的地址，不另存。同站的完整网址只记路径部分，换访问地址也能读到。
- 智绘姬照旧：它给的是图片数据或临时链接，需要兔子镜存一份，否则会丢。
- 1.68.29～1.68.31 期间用柏宝绘画的图，只有在柏宝绘返回 blob 或别的网站链接时才会多存一份（存在酒馆图片目录的「兔子镜」文件夹里），平常柏宝绘给的是本站路径，不受影响。

## 1.68.31 内置重画复核修正

- 重画进行中关掉面板再打开，新面板接着看进度、画完也会刷新，不再卡在「取消这次」。
- 聊天开过分支、改过名的，图存在旧聊天名下：现在先搬到当前名下再翻历史、重画，不会出现「列得出几张却翻不动」。
- 这一面自己的那张还在画时，面板里说明「画完再重画」，三个按钮先灰掉，不会把首画当成重画、也不会把改过的提示词悄悄丢掉。
- 沿用上次提示词时也沿用当时的提示词写法（NAI 5 / NAI 4.5），不受之后改设置影响；智绘姬画的图没留完整构思时，用当时实际发出去的那段整段再画，人物外貌不丢。
- 存档读不出来的那张不让重画（画了也存不进去）；重画时这一面刚被重新加载、没能换上图的，提示「已存档，刷新这一面后显示」；旧版本画的图没留提示词的，说明会重新准备一次提示词。

## 1.68.30 内置生图可以重画、翻历史（在小兔子 → 生图里）

- 每面标题栏的小兔子 → 「▧ 生图」，最上面新加「这一面的插图」：一面里有几张内置生图的图，就能分别选「图 1／图 2…」。
- 「↻ 再画一张」：用这一面生成时写好的同一段提示词、换随机种子再画一次。只花一次生图额度，不调用语言模型；开了生图 LLM 的也沿用上次构思好的提示词，不重新构思。画的时候镜面上的旧图保持原样，画好才换上；能「取消这次」，没画成原来的图不动。
- ‹ › 翻看这张图画过的几张（最多 5 张，按画的时间排），翻到哪张，镜面上就显示哪张。不发请求。
- 「改提示词再画」：展开这张图的提示词，改完按改过的画一次（只影响这次，不改这一面）。
- 原来的手动生图（整面配一张图、构思、草稿）收进下面的「整面配图（手动生图）」折叠区；没开手动生图时不显示。
- 镜面上的图一点没加东西，截图、长按存图都是干净的。

## 1.68.29 画好的图不再「自己」丢

- 查到图会自己消失的真正原因：有些生图服务返回的不是图片数据，而是它们服务器上的一个临时链接，过几小时或几天就失效。以前兔子镜把这个链接原样存进存档，没把图下载到酒馆里，链接一失效图就没了，用户什么都没碰。
- 现在拿到别处的链接时，先把图下载下来存进酒馆的图片目录，存档记酒馆本地路径，以后不随链接失效。下载不下来（对方不允许跨站读取）才只能存链接，并提示你这张图以后可能读不到。这条只对智绘姬；柏宝绘自己会把图存进它的图库，兔子镜不再另存（1.68.32 更正）。
- 同站的完整网址只存路径：在家用局域网地址画的图，换成手机、外网地址打开也读得到。以前存下来的这类带主机的旧地址，显示时也会先按当前地址试一次。
- 已经失效的旧链接找不回来，只能点图框里的「重新生图」再画；新画的会存进酒馆。

## 1.68.28 画好的图读不到时不再挂着坏图标

- 内置生图存档里记的是酒馆服务器上的图片地址。换了设备、酒馆的图片目录被清理过以后，这个文件没了，图框里就一直显示浏览器的「坏图」图标和「这一面的画面」几个字，没有任何提示和出路。
- 现在读不到时先换历史版本里还能读的那张；都读不到就在图框里说明原因，留「重新生图」按钮。只在点按钮时再画一次（要花一次额度），画好后覆盖存档，以后打开就不用再画。

## 1.68.27 正文改过的楼层也能找回旧兔子镜

- 从存档清单看到的真实情况：丢的那几层兔子镜都还在聊天文件里，也没错位，只是那几条回复的正文后来被改过（手动编辑，或被正则／别的插件改写），正文指纹对不上，兔子镜就当成「这条回复换了内容」不再显示，「找回」也只认指纹相同的。
- 现在点「找回旧兔子镜」：别处都找不到时，这一层自己名下有一份、只是指纹对不上、而且这份指纹不属于别的任何一层，就按你明确点的找回放回来，提示里写明「正文和生成时不一样」。镜子里的内容是按当时的正文做的，没改。多面的五版切换一并恢复。
- 正文没改过的层照旧不会被动到；指纹属于别的层的仍走错位找回那条路。

## 1.68.26 设置里能导出存档清单

- 「找回旧兔子镜」还是找不到时，以前没法知道存档到底还在不在。设置「工具」的缺壳扫描下面新加「导出存档清单」：导出当前聊天在三处存档（本机缓存、聊天文件、版本存档）里各记着什么，每层写楼层号、正文指纹、时间、插件版本、长度，再列每层现在正文的指纹（新旧两种算法）和「聊天文件里记的对不对得上」。不含聊天正文和兔子镜内容，可以直接发给别人看。

## 1.68.25 找回旧兔子镜：旧版本算法的指纹也认

- 1.67.9x 那时存档里记的正文指纹和现在的算法不一样（当时连着美化后的显示文本一起算）。1.68.24 按正文找回时只认现在的算法，老用户升级后找回仍可能找不到。现在两种指纹都认，判断「这份存档属于它所在那一层」时也两种都看。
- 模拟了老用户的情况（旧版删过一层没搬家、整段楼层错位、本机缓存已清空、只剩聊天文件和版本存档、指纹是旧算法）：顺着点、乱序点都能逐层找回，被挤占的那份也都能回到自己那层。

## 1.68.24 找回旧兔子镜：楼层号错位时按正文找回

- 有人遇到：以前删过中间楼层（尤其是 1.67.96 以前的版本，楼层号搬家有时没搬对），之后很多层的兔子镜不见了，点「找回旧兔子镜」也找不到。其实存档还在，只是记在别的楼层号下面，比如第 20 层的兔子镜记在第 21 层名下。
- 现在点「找回旧兔子镜」时，这一层自己名下找不到，会在整个聊天的存档里按这条回复的正文找：本机缓存、聊天文件、版本存档三处都看。正文对得上就挂回这一层，提示里写明原来记在第几层名下。不调用模型。
- 不会拿错：那份存档所在楼层自己的正文也对得上时，说明它就属于那一层，不拿。
- 不会弄丢别人的：这一层位置上原来存着的、属于别的消息的那份，先按它自己的正文另存进聊天文件，等它自己那层点找回时再拿回去。另存不了就不挪。找回后这一层的「五版切换」换成找回那面镜子自己的版本，不会混进别的镜子的版本。
- 版本存档读不出来时提示「暂时读不出来，可稍后再点」，不再说成「整个聊天都没有」。
- 从 1.67.93 这类旧版本升级上来的，先更新再点找回；一层一层点就行，先点哪层都可以。

## 1.68.23 横滑复位与跨面继承再补三处

- 横滑区复位：作者给轨道写了 `scroll-behavior: smooth` 时，复位仍会平滑滚回去、路过的都算看过，现在一律瞬间跳回；复位后第一张立刻算看过，和刚接线时一致。
- 横滑区退还给老修复器时，插件补的横向排版内联样式现在也撤干净。
- 跨面继承的「状态没变就不写」改成按聊天和记忆名记，两面同名区域互相改写时不会漏存。

## 1.68.22 新交互大类复查修正

- 横滑区按复位后，插件补的横向排版（一排、按张停靠）被一起撤掉，画廊散成竖排：复位后重新补上，并且直接跳回第一张（平滑滚回去会把路过的都算看过）。
- 用手势甩出去的卡，按复位后停在松手时歪着的位置：现在回到作者写的原样。
- 跨面继承：横滑区记下了滑到第几张但没恢复，现在恢复；带记忆的区域滚动、拖动时每一下都在写本机存档，现在状态没变就不写。
- 写法别名收窄：clock、media、wait、delay、env 这些词不再把旋钮、动画块认成倒计时或环境感应；cards 不再当甩卡；combo 仍是密码顺序；区域里 data-left／data-right／data-card／data-at 这类常见属性不再被补成插件部件。
- 玩法配写法：「按住看倒计时」「按住看导演备注」归按住，「翻转沙漏」归开关，「拖动滚动字幕」归调节，「揭开马赛克」归揭示，不再被新大类抢走。
- 甩卡片不再触发后台整面实测；倒计时每 0.1 秒刷一次结果而不是每帧；倒计时、充能也给 data-rm-when="p>0.5" 这种进度条件用；面被重绘后旧面的横竖屏监听会清掉；横滑在手机上不再多出一条没用的左右按钮；退还区域时新类型的运行时属性一并清掉；写法骨架里「甲:left」这类键保留后缀。

## 1.68.21 同人生图两处补正

- 1.68.20 里写的「Persona 不套原作」太死：自己的 Persona 写明了是原作角色的，现在也照原作形象画；没写明出处的仍按原创人物处理。
- 补一句说明：生图提示词是生成这一面时一起写好的，旧面要重说才会照原作画。

## 1.68.20 同人卡的生图照原作形象画

- 玩同人卡时，角色卡常常只写「某作品里的某某」、不写长相，以前生图提示词只照卡里写明的外貌、没写就不编，画出来是个和原作不像的路人。现在卡、世界书或正文写明了人物出处的，卡里没写的外貌按原作官方形象补（发色发型、瞳色、标志性服饰配件），人物标签最前面加上原作角色名和作品名，生图模型认得的原作角色会照原作画。
- 卡里改过的外貌（AU、换了发色）仍以卡为准；原创人物不套原作；自己的 Persona 只有写明了是原作角色才照原作画。开了生图 LLM 时，它写提示词也照这条。
- 生图提示词是生成这一面时一起写好的，已经画好的旧面不会变；想让旧面也照原作画，要重说那一面。
- 冷门作品生图模型可能不认得，或者想固定某个人的长相：在柏宝绘角色库或智绘姬角色预设里给这个名字（和卡里写的名字一致）配好外貌标签，会优先用那里配好的。

## 1.68.19 插件写法新增 8 个大类；带手势的面整面不再误触切换回复

- 插件写法的大类从 11 个加到 19 个，新增：滚动（横滑浏览一排卡片或分镜，滑到哪张、看过哪些都能配文字）、时间（倒计时、延时显现、到点出现的内容）、滑动手势（左右一甩决定去留，像甩卡那样，也能按钮代替）、节奏连击（按住充能、限时连点、来回摆的指针按中区间）、悬停窥视（鼠标停上去显示注释，手机点一下钉住）、文字遮蔽（正文里的字涂成黑条，点一下揭开）、环境感应（横屏竖屏、深浅色、宽窄屏、鼠标还是手指，各显示不同内容）、跨面继承（一面里选过的、开过的、翻到第几页，在这个聊天里的后一面同名区域打开时恢复，别的区域也能据此显示「上一面选了什么」）。
- 玩法到写法的对应补上这几类的常见动作：划走、甩掉、左划右划配滑动手势；连点、狂点、蓄力、按住几秒配节奏连击；倒计时、等几秒、过一会儿配时间；悬停、瞄一眼、窥配悬停窥视；剧透、涂黑、马赛克、揭字配文字遮蔽；横屏、转过手机、深色模式配环境感应；记住上次、沿用上次、带到下一面配跨面继承；横滑、滚到、一屏一屏、轮播配滚动。规则不变：每面 3 种写法来自 3 个不同大类，先照展现形式自己的玩法配。
- 手机上横着滑动会被酒馆当成左右切换回复（最后一条还会重新生成）。以前只有登记过的手势区域（翻页区、刮擦面等）拦下这种手势；现在只要一面里有任何要动手指的写法（翻页、横滑、甩卡、拖放、重排、旋钮、描画、跟随、揭示），整面的横滑都不再交给酒馆，模型把手势写在没登记的位置也不会漏。代价是这种面的镜面上不能左右滑切换回复，正文和下方的切换按钮照常。
- 维修兔、诊断、写法骨架报告都认得新写法；方言表对新类型的部件名也点得出来。

## 1.68.18 每个展现形式都有自己的玩法

- 以前 307 个展现形式里只有 148 个写了自己的玩法，剩下 159 个只能按标题关键词落到一个媒介大类，用大类里的通用玩法，常常对不上（年度四十问落到「节目与访谈」，给的是「回放刚才那段」；情侣手账落到「人物与身体」）。现在这 159 个也各写了 5 条自己的玩法（比如年度四十问：翻到下一题、点开一题的答案、勾选今年做到的、按住看没写出口的、提交），所有形式都照自己的玩法来配插件写法。
- 玩法到写法的对应补了一些常见动作：送礼物、投票、勾掉、下注、买下这些算收集累积；删除、撤回、保存、确认收货算开关；查看某某算弹窗；扭一下、调到某频道算旋钮；走一步、退回上一格算翻页；消除、用掉、突破、切菜、下锅算触发效果。「播放回放」不再被误认成拖放。
- 全部形式模拟下来，每面 3 种写法里带拖动类的约占四成，弹窗、选择切换、翻页、折叠开合、按住、收集都比以前常见。

## 1.68.17 插件写法大类再细分

- 大类从 6 个分到 11 个：拖动（调节、揭示、进程、旋钮、拖放、视野、跟随、描画、重排）、翻页、选择切换、折叠开合、弹窗、按住、触发效果、收集累积、解谜对位（顺序、连线）、输入、随机抽取。拖动这几种本质是同一种操作，仍算一类。
- 规则不变：每面 3 种写法来自 3 个不同大类，先照展现形式自己的玩法配，剩下的按大类随机补、每类机会一样。大类多了以后，没有专属玩法的面里拖动类出现得更少（约三成），别的玩法轮到得更多。

## 1.68.16 插件写法按大类给

- 19 种插件写法分成 6 个大类：拖动（调节、揭示、进程、旋钮、拖放、视野、跟随、描画）、翻页切换（翻页、多选一、重排）、折叠开合（开关）、弹窗、按住、点按触发（效果、累积、顺序、抽签、连线、输入）。同一类本质上是同一种操作，只是写法不同。
- 每面给的 3 种写法各来自不同大类，一类最多一种：先照展现形式自己的玩法配，形式里两条玩法落在同一类（比如「撕下联系电话」和「贴上新的」都是拖动）只占一个位置；剩下的位置按大类随机补，每类机会一样，抽中了再从类里挑一种写法。
- 1.68.15 里「随机补位不补拖动类」改回来了：拖动是正常的一类，和翻页、折叠、弹窗一样按大类轮到就给。

## 1.68.15 插件写法优先照展现形式来；滑杆类再补三处

- 为什么插件写法老是出拖动：每面给模型 3 种插件写法，以前不够 3 种时会随机补位，滑杆／拖动这一族（调节、揭示、进程、旋钮、拖放、视野）占了六种，随机补进来的常常就是它；「播放」「回放」「运转」这类词也被一律配成进程控制（要真动画，模型几乎不写）。结果很多面明明是问卷、广播剧，却被塞了个滑杆。现在：
  - 展现形式自己写了玩法（比如广播剧的「播放／戴上耳机／拖动进度」）时，3 种全照形式自己的玩法给，不再从大类里掺一项；
  - 滑杆／拖动这一族只在形式的玩法里真写了「拖、刮、撕、转、调」时才给，随机补位不再补这一族；
  - 单纯播放、暂停、回放改配开关写法；只有「拖进度、快进、倍速」才配进程控制。
- 给模型的插件写法说明补了几句最常写错的地方：揭示的遮罩写在盖住内容的那层上、不写在滑杆上；进程控制的部件要有真的 @keyframes 动画；旋钮停在第几格（从 0 数）显示对应内容；效果按过后 data-rm-show="changed" 的内容出现。只在这一面给了这种写法时才发。
- 音轨回放（广播剧）：动画区域里只有一排静态波形细条时，以前拖进度会把整块高度撑大三倍。现在写死像素的宽高不再按比例放大；这种波形补一段可暂停的上下起伏，播放钮开始暂停、进度条拨到对应位置。
- 维修兔的副本实测：拖了滑杆、只有滑杆自己变了（被裁、被挪）的，不再算「画面有变化」，会点名没反应。

## 1.68.14 滑杆类交互三处修复

- 滑杆只包在调节区域里，正文写在区域外面、用 `var(--rm-p)` 算字号或颜色的（比如 AO3 卷面的字号滑杆）：以前正文里只要夹着别的插件区域（比如一张翻面卡），滑杆的值就不往外传，拖了没反应。现在别的区域跟这个变量无关时照常传。
- 揭示区域把遮罩标识写在滑杆自己身上的（比如问卷朱批）：以前一拖滑杆就把滑杆自己裁掉，拖到一半就看不见、拖不动。现在滑杆不当遮罩，拖到底照常显示朱批；以前版本存进存档里的裁切也一并去掉。
- 一次性效果区域（盖章、点火这类）的显示条件写成 effect、stamp 这类词的：以前按下去印章不出来。现在按过以后这些内容都显示，写「!词」的藏起来。
- 方言表新增后两条，诊断里能认出来。写法骨架报告保留模型自己写的 `<style>`（以前被修复器打过标记的会被当成插件样式略掉）。

## 1.68.13 去掉「记录最近画过的动作」

- 内置生图不再记这个聊天最近几张图画过的动作，也不再往提示里加那句提醒。「画这一面自己写到的场面、一次出多面时各面选不同的时刻和构图」这条保留，靠它就够了。

## 1.68.12 复查修补：数值回放、写法骨架、方言表

- 没写真正动画、只靠位置数值的动画区域：滑杆本来就在最左（value=0）时，以前拖滑杆或按播放会把所有数值压成 0（部件缩没、跑到起点外），现在按原样起步、往右再往前走。只认名字像位置、进度、角度的变量（--pos、--x、--progress、--angle），颜色、字号这类不动；复位时正在走的回放会停下，区域外收编的滑杆和播放钮一起复位。按播放后「点了没反应就交给老修复器」的检查不再被卡住。
- 「模型自己的 CSS 管显示」这条方言：现在要求那条规则的选择器里带着驱动写的状态属性，只是给内容上色的规则不算，不会把以前藏着的内容放出来。藏在折叠区里量不到的动画区域不再被报成「没有能动的东西」。
- 写法骨架报告再收紧：中文的键（data-rm-show="某人"）换成统一代号，CSS 选择器里的同一个键换成同一个代号，规则还对得上；文本框、下拉项的值、CSS 里所有引号字符串和注释、模板里的文字也清掉；诊断里的控件名只写长度。

## 1.68.11 方案记录引号写错时不再把正文挂在属性名上

- 模型有时把 `data-rm-vs` 写成双引号包着未转义的 JSON，浏览器会把后半截文字拆成一个个属性名挂在镜面上。独立模式挂载前本来就会转义回去；现在跟随模式拿到已解析的 DOM 时，会把这些零碎属性整个去掉，维修兔读原始消息时也先转义再解析，方案记录能读到。全链路诊断里的方案记录读不到时，会改读按原始消息重新解析的那份。

## 1.68.10 诊断报告只带写法骨架，不带聊天内容

- 全链路诊断下载的报告改成「写法骨架报告」：源代码和实际渲染代码里的文字全换成占位（字×长度），图片和链接地址、模型写的画面提示词和方案记录、聊天归属标记都去掉，只留结构、标识和 CSS。报告正文里原来引用的标题、隐藏内容文字、label 文字、英文词示例也只写长度。这样报告可以直接发给作者当样本，不用先检查有没有聊天内容。
- 复查上一轮的改动，顺手收紧三处：动画区域外的滑杆若已经有模型自己写的处理或老修复器接管，不再被动画区域收编；内置生图只在真画成了以后才记这一幕；「按钮上不认识的标识」只在这个区域一个认识的控件都没有时才报。模型自己的 CSS 管显示的内容，驱动从没碰过的一个字都不动。

## 1.68.9 维修兔实测看内容；模型自己写的显示 CSS 优先

- 维修兔巡逻时的隐藏副本实测，以前只要画面有任何变化就算「有反应」：旋钮转了、按钮变色了，道具卡一张没出来也算过。现在对插件区域再量一次区域里的内容（去掉按钮本身）：按下后只有按钮自己变了、内容没变化的，会单独点名，结论不再写「未发现异常」。只靠位置挪动的部件（赛马）和背景渐变的变化也算进去了，播放钮按下后动画要下一帧才走，也不再误判成没反应。
- 方言表新增一条：显示条件认不出，但模型自己写了 CSS 按 data-rm-index、data-rm-on 这些状态管显隐的，驱动不再强行藏这些内容，交给模型的 CSS。
- 全链路诊断多一行「隐藏副本通用实测（上次巡逻）」，列出没反应和只有按钮变了的控件。

## 1.68.8 插件写法方言表；维修兔会点名对不上的写法

- 新增「插件写法方言表」：模型写的插件交互，意思对、写法和标准不一样的情况集中登记在一处，每条写清怎么认、按什么理解。目前收录五条：开关按钮写在区域外、播放钮和滑杆写在动画区域外、动画区域没写真正的动画、唯一的开关起了名字却写「开了才显示」、旋钮档位写成 item0／stop1 这种名字加号码。以后遇到新写法，加一条就行，不用改驱动本身。
- 全链路诊断新增两行：「插件写法未对上」点名永远对不上的显示条件、写在区域外没人管的部件、按钮上不认识的标识、动画区域里没有能动的东西；「方言表已认出」列出这一面用上了哪几条。有对不上的写法时，诊断的初步判断会直接说出来。维修兔只点名，不猜内容。
- 修复：没写真正动画、只靠位置数值摆放的动画区域（比如赛马），连续拖滑杆时画面会卡在半路不跟手。原因是位置改变时浏览器自动补的过渡被当成了动画。

## 1.68.7 扭蛋机的旋钮、出蛋开关修好

- 旋钮转到第几档就显示第几张内容，模型把内容标成 item0／item1、stop1／stop2 这种「名字＋号码」时，以前一张都对不上，转多少圈结果都藏着。现在按号码对上当前档位（号码从 1 开始的也认）。
- 只有一个开关、但开关起了名字（比如叫 turn），内容却写着「开了才显示／没开才显示」：以前按下去按钮变了，「已出蛋」那段还是不出来。现在这种情况开关开着就算开。

## 1.68.6 赛马直播盘、白昼／夜间告示修好；内置生图不再每张同一个动作

- 动画区域外面的播放钮、进度滑杆（只包住了画面，控件放在下面一排）：这一面只有一个动画区域时，它们归这个区域管。画面里没写真正的动画、只用位置数值摆好的（比如赛马的马在跑道上的位置），拖滑杆按比例前进或退回，播放钮从起点放一遍，再按一次停下。维修兔不再报「缺控件或目标」「滑杆未找到联动目标」。
- 点一下切换白昼／夜间的告示：切过去以后再让维修兔检查，会误报「控件状态变化未带来可验证的正文变化」。其实切换是好的，是维修兔在隐藏副本里切回来时，不知道正文原来写着先藏起来，看起来像没变化。现在副本会带上原来的样子，切回来能正确验证。
- 内置生图：同一段正文出的几面，或者连着几条回复，图里经常是同一个动作（比如一直背着）。现在提示模型画这一面自己写到的场面（画像、照片、镜头里那一刻），不默认照搬正文最新一段的动作；一次出多面时各面换不同的时刻和构图。另外会记下这个聊天最近几张图画过的动作（几个英文短标签），下次出镜面时提醒换一个，这一面写的恰好就是那一刻时除外。

## 1.68.5 不用再配正则；新增地球Online 等八个条目

- 兔子镜自带「不发送兔子镜」：发给模型之前，自动去掉聊天记录里模型写过的旧兔子镜，不用再手动配正则。本轮要写的新兔子镜不受影响，跟随正文也照常生成。设置「工具与维护」里可以关掉。
- 第一次启动时，还会替你把「不发送兔子镜」正则配进酒馆一次；之后你自己删掉的不会再加回。两者同时开着也没关系。
- 新主题／元素：地球Online、楚门的世界、月老 KPI 考核（在「荒诞/超现实」里）。
- 新展现形式：好感度股票行情、快递物流追踪、人生系统设置页、自动售货机 / 扭蛋机、情绪天气预报。描述都只写这是什么，不规定内容和玩法，留给每一面自己发挥。

## 1.68.4 母本库自动存一份进酒馆，数据被清掉也能找回

- 有人在 TT 上遇到：更新以后网页里存的数据被清掉，导入的母本库跟着没了。现在每次导入、启用、改分类、删除母本库以后，兔子镜会自动在你自己的酒馆用户文件夹里存一份整库备份（`rabbitmirror-mother-libraries.json`），不发到别的地方。
- 打开母本库页面时，如果本机一本都没有、酒馆里有备份，会直接给一个「一键恢复」。开着母本库抽签的话，启动后也会提示一次。
- 「换设备」那一栏新增「酒馆备份」：显示上次存的时间和数量，可以手动「现在存一份进酒馆」或「从酒馆备份恢复」。恢复只补本机没有的库，本机已有的不动，抽签总开关也不改。
- 本机被清空后先导入了新库也没关系：存备份时会保留酒馆备份里原有、本机还没恢复的库，不会被覆盖掉；只有在本机上明确删除的库才会从备份里去掉。

## 1.68.3 收藏倍率按条目算准；避重复查

- 收藏倍率：以前收藏在「大家族」里的主题（底下有一串子项的那种）设 ×3，出现得反而比别处只设 ×1 的单项还少；单独一项设 ×10 和 ×50 也没有区别。现在收藏 ×N 的这一项，机会至少是普通一项平均机会的 N 倍，本来机会就高的按本来的再乘 N；同家族的其他项不跟着变多。近期冷却照样管着收藏。
- 跟随模式补回的面，现在记成原来那一批的那一面（和先出的面算同一轮），不再多算一轮；只给真正存下来的面记。
- 独立模式只补一面时，冷却记的是补发那次模型实际选中的签；成品确实存好了才记。补发途中整批重抽了的，按新那批记。
- 近输出短锁里的配色一句，近白、近黑底不再被说成「暖橙」「冷蓝」；深色冷却那句补上「用户明确配色优先」。

## 1.68.2 避重：补发的面也记账，换口味不再一触即发

- 多面兔子镜有一面失败、自动补发以后，先出来的那几面以前不进避重记录（配色、布局、交互都没记）；逐面生成中途卡住留下的面也一样。现在补齐后和补回的面一起按同一轮记下。
- 跟随模式的自动补发和手动「重试这一面」补回来的面，现在也会记进避重。
- 「近三面用过一排按钮切页／翻面展开／滑杆拖动就换口味」以前在多面模式下按近三轮的所有面算，一轮三面时几乎每轮都触发、好几条同时生效。现在按最近三面算，和单面模式一样；「多个入口各显示一段文字」按轮算。
- 近白、近黑的底色（米白纸、冷白、带一点蓝的黑）不再被当成橙色族、蓝色族，用过一次白底不会让下一轮禁掉橙色或蓝色；米黄这类真有颜色的照常算。
- 柔和浅色模式下，多面里夹着长文本时，「第几面用哪个主色族」按真实面序号写，不再错位到长文本面上。
- 长文本面的深色阅读底不再让后面的 HTML 面进入深色冷却。
- 多面预约：别的页面（已刷新、已关掉）留下的预约 30 分钟后就能回收，读不懂的旧记录放久了也会跳过，跟随模式多面不会因为这些一直不出兔子镜；这一轮没登记上时会提示。
- 「按正文挑签」时冷却记的是模型实际选中的签，不再冷却没用上的第 1 张；续篇换成收藏原作的形式时，冷却和记录也记实际用的形式。
- 原本算好了却没发给模型的三处现在接上了：手动「重新生成兔子镜」时同一位置上一版的布局与主色、近输出短锁里的配色一句（色族已经点名的不再换种叫法重复）、多面批次里近期多轮重复的交互家族。

## 1.68.1 拖到底以后，揭开的内容会出来

- 「滑动揭示」类的兔子镜，拖到最右以后，模型写好的「揭开后才显示」的内容（`data-rm-show="reveal"` 这类）以前一直不出来，看起来拖了没用。现在揭到九成以上时，写成 reveal／revealed／done／full／open 的内容都会显示，往回拖再藏起来。
- 有的揭示滑杆一打开就停在最右边（已经揭到底），往右拖不动。现在这种情况从最左开始。
- 写给模型的说明里补了一句「揭到底时 data-rm-show="done" 的内容出现」。

## 1.68 收藏里「变成一串代码」的小剧场能看了

- 有的小剧场，模型把整页网页（`<!DOCTYPE html><html>…`）写进了兔子镜里的代码块。聊天里靠酒馆助手把它当网页显示，看起来正常；收藏起来以后没有这一层，打开收藏（尤其是正文 roll 掉以后）就只剩一串代码。现在打开收藏时，会把这种整页代码拆成「样式 + 页面内容」放回兔子镜里显示，收藏夹的缩略图也一样。以前已经收藏的也能这样看回来，不用重新收藏。
- 只认完整网页（有 `<html>` 或 `DOCTYPE`），普通的代码示例不动。网页里的脚本不会运行，样式照常限定在这一面里，不会影响酒馆页面；写给整页的背景等样式改成作用在这一块上，「撑满一屏高」的高度去掉，免得撑出一大片空白。
- 1.68 同时包含 1.67.95～1.67.100 的全部修复。

## 1.67.100 设置、跟随模式、插图和卡顿的零碎问题

- 「恢复默认设置」以前点了等于没点：酒馆要等约 1 秒才真正存盘，页面马上刷新把它打断了。现在先存好再刷新。
- 跟随模式：页面刚打开就发消息时，负责收尾的部分可能还没加载，这一条回复会漏掉避重记录、挨打猫扣轮次、缺面自动补发。现在发消息时会提前把它叫醒，加载好后补处理这一条。
- 世界书抽签最多选 80 条。以前超出的部分悄悄丢掉，「全选」反复点也没反应；现在会提示选上了多少条、还差多少。
- 设置里「提前生成」那一页，每次打开都按当前聊天显示。以前换了聊天还显示上一个聊天的状态，这时保存会把上一个聊天的设置盖掉。
- 清除抽签历史后，「本轮不用近白底色」的提醒不会再带着。
- 跟随模式自动补发一次补回好几面时，以前只有第一面存进记录，刷新后其余几面会变回失败卡；现在都存下。外置显示时补回来的面也会按屏蔽词替换了。
- 跟随模式单面手动重试最多等 10 分钟：以前宿主一直不回时这条回复一直卡在「正在重试」，只能刷新页面。
- 多面跟随的登记会清掉半小时以前的旧登记；以前在几个聊天里中途切走几次后，多面跟随会悄悄不注入。
- 插图：每一张图的旧版本只留最近 4 张，整张存在本机的旧版本只留最近一张，重画几次不会再把本机空间占满。维修兔修过的面，修之前画的手动插图入口不会消失。
- 手动时机下，自己跳过没生成的楼层，刷新后不再挂「找不到已保存兔子镜」的卡（想补可以用设置里的「重新检查缺壳楼层」）；真的生成过又不见了的楼层照旧挂卡。
- 收藏「去掉重复」先把图鉴里的格子改指向留下的那一份，改好了再删；以前先删后改，图鉴改失败时那些格子会默默变空。
- 卡顿：
  - 长聊天里流式回复时，不再每 0.12 秒把整个聊天同步一遍。
  - 点收藏星不再把所有收藏重新解析一遍。
  - 拖完物件那一下不再在后台把整面复制一份去实测。
  - 维修兔检查时少复制一遍整条消息。
  - 点按钮后的复查只看可能塌掉的那几个按钮，不再量整面所有按钮。
  - 手动时机下已经作废的生成请求不再一直留着。

## 1.67.99 模型写的样式不能再影响整个酒馆页面

兔子镜里的样式本来只作用在这一面里。下面几种写法以前能绕过去，改到整个酒馆的界面；模型一般不会这么写，但角色卡或世界书里如果有人故意埋了指令，就可能发生。

- 嵌套写法里 `:has(&)`、`:not(&)` 这类把 & 放进括号的子规则，和紧跟 & 的兄弟选择器（`& + *`），目标可能在兔子镜外面，整条去掉；`&:hover`、`& .x` 这些照常保留。
- `@scope`（能指到整页）、`@property`（能改掉酒馆主题颜色变量的类型）、`@font-face`（能把常用字体名换成别的字体）整段去掉。
- `position: fixed` 一律改成 `absolute`：以前只拦「四边贴满」的写法，尺寸写大一点或边距写成 -1px 就能盖住整个酒馆界面。改成 absolute 后只在兔子镜附近叠放。
- `image-set(...)` 里的图片地址以前只检查到第一个右括号，前面放一个渐变就能把外部网址藏过去；现在整段检查，用 `var()` 从别处取地址的也不要。
- SVG 动画里改链接地址、图片地址、事件的那几种去掉（改颜色、大小、位置的动画照常保留）。
- 图片上的 `name` 去掉：`<img name="querySelector">` 这类名字会盖掉网页自带的功能，挂着这一面时整页出错。
- 作用域后面先接 `:not(...)` 再接兄弟选择器的写法，也会被重新限定在这一面里。

## 1.67.98 维修兔：修坏了不存、能退回、不修错版本

- 空壳兔子镜（只有标题和样式）点维修兔时，维修兔会加一段「原始输出为空壳」的说明。以前这段说明会被当成正文存进聊天记录，刷新后这面不再被认成空壳，说明里写着「不会改写聊天原文」却改了。现在这段说明只在眼前显示，不保存，收藏、版本记录里也不带。
- 修完反而多出新问题，或者有维修模块中途出错时，这一版不再保存：页面上照样能看到，刷新后回到维修前，维修兔会写明「这次结果没有保存」。以前不管修好修坏都存，之前修好的那一版会被盖掉。「修完多出的新问题」以前因为比较顺序写反，永远查不出来，现在能查出来了。
- 跟随模式的兔子镜修过之后，「⏪ 恢复到初始」可以退回维修前的样子（以前是灰的点不了）；退回时也会停止重绘时自动重放这次维修。
- 维修进行中切换了版本或重说完成，维修会停下，不会接着修到另一版上再存进去。
- 「空白或显示代码」这类修复以前会把同一条消息里你要的普通 HTML 示例代码块也渲染成卡片。现在兔子镜外面的代码块只有长得像兔子镜（有 details 和 summary）才会接回来。

## 1.67.97 交互急救里互相打架、误伤的地方

- 控制区和内容区分开写的开关（`.房间:has(#灯:checked) div` 这种）：以前补上的规则丢了「房间」这一层，目标写成 div 这种标签名时，勾一下整面所有 div 都被强制显示。现在只作用在房间里面的那几块。
- 「下一步」式翻页（选中第 1 页时把「下一页」按钮显示出来）以前被当成「高亮点错了」改掉，卡在第一页翻不动。现在规则里改的是显示、透明度、尺寸这类时不再改它。
- 选择题「答对变绿、答错变红」：以前两条都套上，点对的答案也变红。现在只用外层对得上的那条；一条都对不上（模型写错了外层）时照旧全部兜底。
- 勾选框的小图标、印章图片（data URI 里带分号的图片地址）以前会被从中间劈开，图片丢失，坏的样子还会存进存档。现在整段图片地址保持完整。
- 滑杆切换的分段以前一律改成竖排，横排、网格会塌。现在按这一段本来的排版方式显示。
- 手机上滑杆旁的 −／＋、横滑旁的 ←／→ 按钮，在开关区域里时点一下会顺带把整块翻过去，现在不会了。
- 拖动、排序、涂画过的兔子镜，收藏或重新打开后，物件停在原处，「放回」「复位」都点不动。现在重新打开时从头开始，和「已投入」一样。
- 很常见的噪点纹理背景（图里写着 100%）以前被当成不安全整条删掉，现在能正常显示，图里的内容照样逐项检查。
- 样式里同时有一个外链图片和嵌套写法时，以前整份样式都被删掉、整面没了样式。现在只删那一个外链图片。
- 电脑上鼠标悬停显示的卡片，以前点一下反而关掉，现在点了不关；手机上照旧点一下显示、再点收起。
- 正文里写着「继续」的按钮不再被当成动画暂停键（以前点了整面动画停下、剧情却推不动）；已经被别的修复接管的按钮也不再接成暂停键。
- 手机上「按住查看」按约半秒会被长按菜单打断、自己收回去，现在按住不会弹选字或存图菜单。
- 在旧手机上收藏的弹窗，换到新浏览器打开时点了看不见，现在打开时会撤掉旧手机留下的隐藏样式。

## 1.67.96 少白花钱、少丢东西

- 更新：酒馆更新失败时，不管是本地有改动还是酒馆服务器连不上 GitHub，回的都是同一个错误。以前一律当成「本地有改动」直接用 GitHub 覆盖重装，服务器连不上 GitHub 时可能卸掉了却装不回来。现在先问你要不要覆盖重装，并说明风险；选取消就什么都不改。读不到当前分支时不覆盖。
- 跟随模式自动补发：
  - 只缺一面时，补回来的那一面以前总被判成「结构不完整」丢掉，请求却已经花了钱，还会再发一次。现在能正常收下。
  - 补发等太久时，上一次请求其实还在跑，以前马上又发一次，两次都花钱、结果都丢。现在等太久就停下，提示可以手动重试，已出的面保留。
- 自动重试：密钥不对、没有权限、被限流、参数或模型不对时不再自动重发（马上再发结果一样，只会多花钱，限流时还会越试越严）。
- 一面一面生成时，20 分钟的总等待上限改成每一面各算各的；中途因为等太久停下时，已经出好的面会保留，只补没出的。
- 内置生图：聊天开了分支或改了名以后，旧兔子镜的图会按原来的楼层和提示词找回来放上，不再全部重新画。
- 存储满时为了记一笔抽签账腾地方，只删已经确认存进聊天文件的本机缓存，刚出、还没存进聊天文件的兔子镜不删。
- 重说失败时那层「这一版失败」的遮罩不会再被一起存下来（维修兔保存、改设置、收藏都会碰到），刷新后不会变成空的一面。
- 删掉中间楼层后，页面上已经挂着的兔子镜跟着改楼层号；挂在别的楼层下面的兔子镜不会再被按旧楼层号认走，不会两面合到一起或挪到别的楼层。被删消息留下的兔子镜会移走。
- 删楼层改完楼层号后，会请酒馆稍后存一次聊天（同样等聊天加载完、没在生成时才存），免得下次打开时把本机正确的版本当成旧的清掉。
- 手机上在翻页的兔子镜里左右划、转旋钮、刮开整块揭示区时，手势不会再传给酒馆，不会顺带切换回复或重新生成。

## 1.67.95 只剩一个标题的兔子镜能看到了

- 有的兔子镜打开只剩标题，正文整面不见。原因：模型把「勾选后显示」写成了「勾选框后面紧挨的那个 div」，兔子镜帮它补「没勾选时先藏起来」的时候，没限定是哪个 div，结果整面所有 div 都被藏了。现在只藏勾选框后面真正挨着的那一块；如果那一块就是按钮本身（藏了就没地方点），就不藏。已经变成只剩标题的旧兔子镜，打开时会自动去掉这条错误的规则。
- 同一类兔子镜里，按钮下面那段「点了才出现」的结果，按钮上写的不是「点击／查看」这类字样（比如「确认落定院落修葺方案」）时，以前点了没反应。现在按钮上写「确认」「提交」等字样，或者那块本身就画成按钮，点了都会展开结果，再点收起。

## 1.67.94 收藏里能看到内置生图的图

- 收藏夹里打开一面，内置生图的图框以前是一个破图标。原因：图存在本机、按「哪个聊天、第几楼、第几个 swipe」找，收藏里打开时不在那条聊天里，找不到。现在用收藏时记下的聊天、楼层和 swipe 去找，把当时画好的图放回去；以前收藏的也一样能找回（只要那张图还存在本机）。只放回已经画好的图，从不发生图请求。找不到图时不再留破图标。
- 收藏打开后标题下面那句「收藏走本机净化与挂载，不写入主楼 Prompt」去掉了，只留角色卡名字。

## 1.67.93 能给以前的楼层补兔子镜；图鉴按正文收录，排版和节气一样

- 补楼层：设置里选好缺壳扫描范围，点「重新检查缺壳楼层」，范围内没有兔子镜的回复下面都会挂上卡（以前没生成过的楼层也算），点卡就能生成。不点的时候照旧安静，只在生成过兔子镜的楼层之后自动补卡，换新角色卡不会每条都挂。
- 收藏图鉴：以前只认标题、小标题，或者正文里正好一整行就是格子名；模型不按格式写标题时就收不进去。现在小剧场正文里写到格子名也算：两个字以上的词在正文任何地方出现就收录，单个字（猫、月这种）太常见，仍只看标题和整行。英文词至少三个字母、前后不连着别的字母。手动关联照旧优先。
- 自定义图鉴的排版改成和「二十四节气收集」一样：小格子、半透明、默认收起，未收集的格子淡淡的，点亮的格子直接打开那一面。

## 1.67.92 移除心迹回廊表情包；补回「有入口就能点进去」

- 心迹回廊表情包相关的功能（1.67.86、1.67.87、1.67.90 加的）从兔子镜里整个拿掉：不再读取表情清单，不再提示模型写表情包，小剧场里的表情标记和 `[表情:…]` 文字暗号也不再换成图片。之前生成的小剧场里留下的表情位置不再显示（不会出现破图）。心迹回廊的头像显示不受影响，和以前一样。
- 交互规则补上一条：画面里看起来能点的入口（按钮、标签、链接、头像、用户名、帖子或商品卡片、门、抽屉、信封、文件夹等）都要真的能点开，点了出现对应的内容或变化；做不出内容的就不要画成入口的样子。

## 1.67.91 柔和浅色不再总是绿、紫、蓝

- 柔和浅色以前只给一种风格和几个举例色，具体用什么颜色由模型自己挑，模型一说「柔和」就几乎总落到雾绿、雾紫、雾蓝。现在由兔子镜给每一面指定一个主色族（红、橙、黄、绿、青、蓝、紫、粉里挑），背景和主承载就在这一色族里取浅色：
  - 避开近三轮实际用过的色族，也避开最近几次指定过的；
  - 连着两次是冷色（绿、青、蓝、紫）时，下一次一定给暖色（红、橙、黄、粉）；
  - 多面时每一面给不同的色族；
  - 形式自带的标志色仍然优先。黄色族指淡柠黄这类清亮的浅黄，不是米黄。

## 1.67.90 表情包只在用得上的面里读取

- 兔子镜只在这一面的形式本来就有人发消息、发帖或评论时（社交媒体、实时通讯、短信、论坛、贴吧、弹幕、直播、评论系统、小红书、查手机等），或者你在指令里写了聊天、私信、群聊、朋友圈、弹幕这类要求时，才去心迹回廊读表情清单；其他面不读，提示词和以前一样。
- 没装心迹回廊，或者当前角色没有表情包时，什么都不读。
- 表情包提示改成按小剧场本来的生成方式写：整面都由模型来写，你不用在里面发任何东西，跟随正文生成和单独生成都一样。面里写到谁的发言就用谁的表情：角色用自己的，写到你的发言时用你的，双人和其他两边都能用；原本会写成 emoji 或「发了个表情」的地方换成真正的表情包。

## 1.67.89 少一点「一排按钮切换内容」

- 最近每一面几乎都带一排按钮切换不同内容（标签页、分页按钮），哪怕同时还有别的交互。现在近三面里有两面用过这种按钮切换时，这一面就不提供多选一、翻页这两种插件写法，并提醒模型这一面不用成排按钮或标签切换内容，换成直接作用在物件上的操作。换过一轮以后照常可以用。

## 1.67.88 内置生图不再把人裁掉

- 图框写成一条很扁的横幅、画出来的图却是正常比例时，以前图会铺满图框，上下被裁掉一大截，人物的头、手都看不见。现在图框和图的比例差得多时就不裁了：图框改成和图一样的比例，整张图完整显示，图框的边框、圆角等样式照旧。比例差不多的照旧铺满。

## 1.67.87 表情包用得更主动，文字暗号也能显示

- 表情包和头像一样直接从心迹回廊读取，不需要世界书：兔子镜写小剧场时就会拿到当前能用的表情清单。
- 小剧场里只要有人在发消息、发帖或评论（聊天界面、私信、群聊、朋友圈／微博／论坛帖子、评论区、弹幕、短信、留言条等），会主动在合适的发言里用上表情包；原本写成“发了个表情”、用 emoji 充数或「表情包轰炸」之类说明的地方，也会换成真正的表情包。用户也可以发角色的表情。
- 模型如果在小剧场里照着主聊天写了 `[表情:名字·表情名]` 文字暗号，心迹回廊认得的会自动换成表情图；认不出的原样保留。
- 不装心迹回廊、或者当前角色没有表情包时，兔子镜和以前完全一样。

## 1.67.86 小剧场能用心迹回廊的表情包

- 和心迹回廊的头像一样：装了心迹回廊、当前角色做过表情包时，兔子镜在写带 HTML 的小剧场时会知道有哪些表情可用（只给名字和一句意思，不给图片地址）。
- 小剧场里本来就会发表情包的场景（聊天软件、私信、群聊、弹幕、评论区等），模型可以写 `<img data-rm-sticker="名字·表情名">`，兔子镜在本机换成你做好的表情包图片；没人发表情的场景不会硬塞。
- 只换这条消息原文里确实写了的表情；名字对不上、表情被删掉或没装心迹回廊时，什么都不换，原样保留。换上的图片不会存进成品，只在本机显示。
- 两个插件仍各自独立，不装心迹回廊时兔子镜和以前完全一样。

## 1.67.85 本机两份缓存缩小，只删能确认「聊天里已经有」的

- 本机成品缓存的目标从约 1.6MB 降到约 0.8MB，旧版本备份从约 1.75MB 降到约 0.5MB，兔子镜在这台设备上占的本机存储会少一大半，不再把位置占满。
- 超出目标的部分不是一刀切删掉，只删能确认不会丢的：当前聊天里这一层的成品和缓存一样（或这一层已经被你删掉）的；别的聊天里不是最新的那些（那些聊天早已保存过）；旧版本备份里成品缓存或聊天里已经有同样内容的，以及只用来回退的更早版本。
- 还不能确认的照旧留着：当前聊天里聊天数据没对上的、别的聊天最新的那一条、旧版本备份里每一层最新而哪里都没有的。留着的上限仍是以前的大小，最坏情况和以前一样。打开一个聊天、同步过以后，它的缓存就能确认，下次写入时自然缩小。
- 聊天文件里的成品、翻版用的版本存档都不动。

## 1.67.84 新成品做好后请酒馆稍后存一次聊天

- 以前兔子镜做好成品后只放进聊天数据里，要等酒馆下次自己保存聊天（比如你再发一条消息）才真正存进聊天文件；这中间刷新、闪退，刚生成或刚修好的那一版就可能回到之前的样子。现在生成完、维修完、重说完、续写完、切换版本后，会请酒馆「稍后存一次」，聊天文件尽早拿到这一版。
- 只在安全的时候请求：酒馆不在生成正文（在生成就等它结束，最多等两分钟）；还是写入时那条聊天；聊天已经加载完整、写入的那一层还在原位。任何一条对不上就不请求，照旧等酒馆自己保存。几秒内的多次请求合成一次。
- 本机的成品缓存和旧版本备份这次不动。

## 1.67.83 本机存储满了先腾兔子镜自己的旧版本备份

- 维修后、生成后保存成品时本机存储写不进去：以前兔子镜只会删自己别的楼层的成品缓存，删完还写不进就报「保存失败」。现在先从兔子镜自己在本机多存的「旧版本备份」里腾地方，最旧的先删，腾出够用的地方就停，再把这次的成品写进去。聊天记录里的成品和版本存档都不动，别的插件的数据也不动；只是本机那份旧版本备份会少几份最旧的。

## 1.67.82 保存失败时说清楚是谁占满了本机存储；卡片式解封能打开

- 维修后提示「镜面保存失败」、或右下角出现「有几份成品待备份」时，多半是这个酒馆网址下的本机存储满了（手机浏览器通常只有 5MB 左右，所有插件共用）。现在提示里直接写出谁占了多少：兔子镜插图、兔子镜成品与设置、其他插件和酒馆各多少，其他里最大的是哪一项。只查看，不删任何东西。
- 插件写法的「逐个解封」：解封按钮点了以后，样式要的是外层那张卡片带上「已解封」，可状态只写在按钮上，卡片永远打不开。现在按钮解封时，外层卡片也跟着变成已解封；「重新封识」时恢复原样。开关、单选的按钮同理。

## 1.67.81 生成过的兔子镜不见时至少留一张卡；按住、盖章、揭帕三类交互修好

- 这一层以前生成过兔子镜（消息上有归属标记，或聊天里、本机存档里有这一层的记录），可同步完以后既没恢复出成品、也没挂卡：现在补一张「暂未找到与这条回复对应的已保存兔子镜」卡，可以点「找回旧兔子镜」或重新生成。不会自己发请求；正在生成的、你删过的、正文模式的照旧不挂。
- 插件写法的按住：样式写成「按住时，区域里的 .xx 发光、冒热气」，可发光的东西其实画在上面的画面里、不在按住区域里面，按了没变化。现在按住时直接让画面里那几样变，松开恢复。
- 插件写法的「触发效果」：要弹出来的部件（比如盖章后的通行证）本身是藏着的，插件只会重播已有的动画，点了没反应。现在点一下就把它显示出来，并从头播一次入场动画；复位时藏回去。
- 勾选框类交互（揭开丝帕之类）：以前维修过、保存时带着「已揭开」的样子，重新打开后取消勾选，丝帕还卡在揭开的位置。现在取消勾选时，把维修时写上去的「勾选时」样式清掉。

## 1.67.80 插件写法点了没反应时自己找结果；没生成过兔子镜的聊天不再每条挂卡

- 插件写法的交互，插件把状态改对了、画面却没跟上时，现在会自己找结果：
  - 滑杆（比如推动时间让晨光变暮色）：滑杆写在旁边，画面写在另一块，画面收不到滑杆的数值，拖了不变。现在数值也会送到用它的那块画面上。
  - 样式写了「按下／打开时变亮」，可那个元素自己身上又写死了同一项（比如 `opacity:.4`），状态到了也压不过它。现在状态到了就按样式里写的变，状态撤掉时恢复原样；一开始的样子不动。
  - 以上都接不上、第一次点下去画面一点没变（插件自己补的描边、一直在跑的动画不算）：当场在看不见的副本里试老修复器，试出来能动才换过去，并替你把刚才那一下再点一次，不用白点。每块只查一次。
- 缺外壳卡（「暂未找到与这条回复对应的已保存兔子镜」）只挂在这个聊天里已经生成过兔子镜的楼层之后。换一张从没生成过兔子镜的角色卡，不会再每条回复下面都挂一张。
- 正文整段画在内嵌页面里的美化卡，外面一个字读不到时，改读内嵌页面里看得到的字，不再报「正文在可见性检查和标签过滤后为空」。外面有字时照旧只读外面。
- 宿主生成中途停掉、没正常收尾时，最后一条回复不会一直既没有兔子镜、也没有重试卡。

## 1.67.79 开关按钮写在区域外、样式按属性翻转、按住的结果写在区域外，都能接上

- 插件写法的开关：
  - 开关按钮写在开关区域外面（区域只包住了卡牌，按钮放在下面一排）：这一面只有一个开关区域时，外面的 `data-rm-toggle` 按钮也归它管，点了和点区域本身一样。
  - 样式写的是「区域带某个属性值时翻转」（比如 `[data-rm-state="reverse"] .card-inner` 让牌倒转），却没有东西去改这个属性：开着时把这个属性值写到区域上，关上时撤掉。
- 插件写法的按住、开关：区域里没写「按住时显示什么」、样式也不回应它的状态，而紧挨着它后面有一块藏起来的内容（模型原本写了脚本去显示，脚本被拿掉了），这块就当作它的结果：按住或开着时显示，松开或关上时藏回去。
- 维修兔实测时跳过插件的「复位」按钮：初始状态下本来就没东西可复位，按了不变不再算「点了没反应」。

## 1.67.78 插件区域里点了没反应，当场交给老修复器

- 以前插件写法的区域里有按钮点了没反应，要等你点维修兔「修交互」才会接力给老修复器。现在点了没反应就当场接力：这一下点击结束后，在看不见的副本里只对被点的这一块实测一次，退还给老修复器再测，没反应的变少、原来能用的仍能用，才在真实页面照做，之后再点就有反应了；接管过的块照旧记在本机。每块只试一次，没点过的块不扫描，打开镜面时不多做任何事。
- 维修兔「修交互」「全面维修」照旧一次处理整面。

## 1.67.77 正文生成完以后不再被「缺壳卡」截胡

- 自动生成时，正文刚结束、兔子镜还没开始生成，有时先跳出「暂未找到与这条回复对应的已保存兔子镜」这张卡，然后就不生成了。原因：这张卡本来是给网络中断、闪退后补的，它一挂上就会记一条「停止」，而自动生成的流水线从正文结束到真正发请求中间有几拍，同步抢在前面挂了卡，这一轮的自动生成就被这条「停止」永久挡住。现在：
  - 这张卡不再拦自动生成。它只表示「本机没找到成品」，这一轮并没有发过请求，随后正常授权的自动生成照常发，发之前把卡换成「正在生成」。
  - 正文刚结束的那条回复（宿主生成还在进行，或结束后 45 秒内）不挂这张卡，给流水线登记的时间。流水线真的没接上，45 秒后照旧挂卡，可以手动重新生成。
- 旧的那条路径没动：网络中断、闪退后重新打开，范围内缺外壳的回复下面照旧挂卡。

## 1.67.76 生图提示词按「人物动作在前、边框在后」写；角色库标签不再和模型标签混拼

- 童话塔罗的画面描述改成先写人物和经典姿态（一两个人、一个主要动作），再写场景和画风，最后用一两个标签或一句话写边框。以前边框、编号、牌名饰带写在最前面，抢走了画面的重点；编号和牌名的具体字也不再写进提示词（多半画成乱码，或被负面词里的 text 去掉）。
- 没开生图 LLM 时，画面描述要求一幕只写一个主要动作、姿势简单清楚，不写多人复杂交叠。
- 人物标签栏：角色库里配了标签就只用角色库，模型另写的标签只给角色库里没有的人。以前两边拼在一起，会出现 `1girl` 和 `1 girl`、`pale skin` 和 `snow-white skin`、冷脸和笑脸这种重复或打架的标签。自然语言外貌仍然两边都带。

## 1.67.75 投放类交互放进去有反应；童话塔罗的边框跟着画面设计

- 插件写法的拖放（把签纸、物件放进槽里）：以前放进去以后，槽里写着「放进去才显示」的内容不会出现，物件还会整个盖在槽上，看起来像没反应。现在：
  - 放进对应的槽，这件物件的键就算当前状态，`data-rm-show="键"` 的内容会显示出来（`placed` 表示放进了任意一件）；
  - 槽里自己写了这种内容时，物件不再盖上去挡住它，而是留在原处变淡，表示已经投入；点「放回」或复位就恢复。槽里没写内容的（拼图、摆放类）照旧吸附到槽上。
- 童话塔罗：边框不再每次都是同一种奶油底金框，改成跟着这一幕现编（比如雨夜破庙用青苔石柱和藤蔓、花园用蔷薇枝和缎带），编号和牌名饰带也做成边框的一部分；网页上不再另外给图套一层牌框和编号条。

## 1.67.74 没开生图 LLM 时的生图请求再查一遍

- 只收一段提示词的生图渠道（比如智绘姬）：选 NAI 5 时，模型另写的那行场景英文标签以前没发出去，只发了自然语言画面和人物外貌。现在按「场景标签 → 自然语言画面 → 逐人外貌」三段一起发。
- 某个出场人物这种写法下一点外貌都没有时（比如标签写法下只写了名字），不再发一个空的人物过去。

## 1.67.73 童话塔罗画出来要像一张牌

- 童话塔罗画出来常常只是一张场景插画，看不出是塔罗牌。原因是画面描述没写牌框，而且生图规则一律要求「画面不出现文字」，编号和牌名饰带画不进去。现在画面描述先写整张牌的样子（奶油色牌边、金色花饰边框、顶部罗马数字、底部牌名饰带、正面平视、四角完整），再写中央牌画；这类要求画成完整物品的形式，牌框、编号和饰带可以画进去。
- 开了生图 LLM 时也一样：要求画成一件完整物品（塔罗牌、海报、卡牌、封面）时，按物品画，保留边框和装饰，不改成没有边框的场景插画。

## 1.67.72 新展现形式：童话塔罗

- 内置展现形式新增「童话塔罗」（在「神秘学与符号学 · 西方神秘学」下面）：依据当前剧情的矛盾和关系转折选一张大阿卡纳，把角色画进一张完整的竖版童话牌面，配吐槽式牌名、UR／SSR 徽章、牌面象征、剧情对应、命运启示、羁绊值和一段童话小剧场，可以抽出、收回命运签。
- 开了内置生图时，整张牌由内置生图画出来；没开时用样式画出牌面。
- 这个形式的制作要求较完整，不论「参考内容」选哪个档位都整段发送。
- 童话塔罗不套用旧塔罗形式的外链实体牌图规则，不会再放原版牌图。

## 1.67.71 图框被藏起来、旁边放外链图顶替时，画好的图照样显示

- 模型有时把图框自己写成隐藏（`display:none`），再在旁边放一张外链图片顶替（比如塔罗牌原图），结果画好的图永远看不到，显示的是那张外链图。现在图框只被它自己这样藏住时会显示出来，和图框并排放在同一层的外链图片不显示（原文不删）；由交互控制显隐的图框不碰。
- 生成时也告诉模型：图框本身不要隐藏，需要画面的地方不另放外链图片顶替。

## 1.67.70 NAI 5 下每个出场人物也有英文外貌标签

- 没开生图 LLM、选「自然语言＋标签（NAI 5）」时，角色库里没配外貌的人物，标签栏以前是空的，只有一句中文外貌，发型这类细节容易画错。现在生成时让模型给每个出场人物多写一行简短外貌英文标签（4～8 个，比如 `1boy, black hair, high ponytail`），依据角色卡、Persona、世界书原文，没写的不编。
- 人物标签栏：角色库里配好的标签在前，模型写的补在后面，同一标签只留一个；角色库的外貌不会被覆盖。

## 1.67.69 NAI 5 的自然语言和标签各进各的栏

- 没开生图 LLM、提示词格式选「自然语言＋标签（NAI 5）」时，以前图框里只有一段自然语言画面描述，这段话被放进了标签栏，自然语言栏反而是空的（1.67.62 去掉重复时只留了标签栏这一份）。现在：
  - 生成时让模型在图框里多写一行英文短标签（人数与性别、镜头构图、各人动作与衣着、场景、光线），放进标签栏；自然语言画面描述放进自然语言栏，两栏不再塞同一段话。
  - 出场人物：角色库里的英文标签放进人物的标签栏，角色库的自然语言外貌和模型写的外貌放进人物的自然语言栏。
  - 旧镜面没写这行标签时，照旧只发画面描述这一份，不会重复发。
- 选「标签（NAI 4.5）」时不变：全部写英文短标签，不发自然语言。

## 1.67.68 图框里只显示画好的图；没开生图 LLM 时画面描述写得更细

- 模型有时在图框里另放一张外链图（比如塔罗牌原图），和画好的图挤在一个框里各占一半。现在图框只显示画好的图，框里别的图片、视频不显示（原文不删）；生成时也告诉模型图框里只放画面描述，不放别的图。
- 没开生图 LLM 时，画面描述由兔子镜这次请求顺手写，以前要求很简略（几个人、镜头、衣着动作、场景、光线），画出来常常空泛。现在用和生图 LLM 同一套细节要求：每个人在画面哪里、身体朝向、当下动作、手和物件、视线与表情、当时衣着，地点里的具体物件与前中后景，时间、光源方向和镜头距离；标签写法按这个顺序写全，自然语言写法写成一段约 100～200 字能直接画的画面。

## 1.67.67 标题统一成【兔子镜：标题】

- 标题栏只显示一个【兔子镜：标题】。模型常把标题写成「【兔子镜：【主标题】副标题小字】」或「【兔子镜：主标题】小牌子」，标题栏里就出现套着的括号和一串小字，又长又宽。现在：
  - 主标题外面再套的【】去掉；
  - 主标题后面另写的副标题、小牌子、操作提示（比如「大阿卡纳 · 力量」「点击展开……」）不在标题栏显示；
  - 括号和后面的字写在同一段里的（比如「【第一夜】雨中的告白」），去掉括号、中间用「·」连起来，字一个不少；
  - 只改标题栏的显示，镜面原文不动；收藏、重说、备份里的标题照旧。
- 生成时也告诉模型：summary 里只写【兔子镜：标题】，不再套【】，不加副标题、标签或小字。
- 1.67.66 改的「标题栏只占一行、太长显示…」撤回，标题栏恢复原来的排法。

## 1.67.66 标题栏只占一行

- 兔子镜的标题栏改成一行：标题在左，收藏、维修兔、关闭在同一行右边。以前标题长一点（比如带副标题小牌子）就折成两行，工具再被挤到第三行，标题栏又高又占地方。现在标题太长时末尾显示“…”，点标题照常展开或收起。
- 模型在标题里写的小标题、段落或换行也排进这一行，不会把标题栏撑高。

## 1.67.65 开关写成 data-rm-toggle="true" 也能展开内容

- 插件写法的开关，模型常把按钮写成 `data-rm-toggle="true"`（当成“这是个开关”的标记），内容却写 `data-rm-show="on"`。以前插件把 `true` 当成开关名字，点了按钮状态变成“开”，内容仍然藏着，看起来就是点了没反应。现在不写、或写成 `true`／`yes` 的开关都按默认的 `on` 处理，内容写 `on` 或 `true` 都能跟着展开、收起；写了自定义名字的多个开关（比如 `1`、`2`、`3`）不受影响。已经保存的这类镜面打开后直接能用，不用重新生成。

## 1.67.64 参考内容「完整」档把抽中条目的原文全部发出

- 「完整」档以前和「均衡」一样有字数上限（每条最多约 900 字，整组最多约 1500 字），长一点的条目后半段会被截掉。现在抽中的每一条主题和展现形式都发原文全文，摘要也不截断，一字不落；导入的母本库条目同样整条发出。
- 「精简」「均衡」不变：精简只发摘要；均衡再带原文开头（主题每条约 180 字、展现形式每条约 360 字）。
- 设置里三个档位的说明改成直接写清各发什么。
- 完整档的 Prompt 会更长；如果超过请求字数上限，会和以前一样提示并且不发送，可以在设置里调高上限。

## 1.67.63 多面镜里单独重说的一面能合并回原多面镜，失败原因写成人话

- 多面镜里某一面没生成成功，点这一面的「↻ 重说」生成好以后，以前有时只能单独显示成「本次成品已单独显示……尚未合并到原多面镜」，刷新就没了。原因是合并时只认页面上正在显示的那一份当底，而那一份可能带着被浏览器拆坏的属性（比如模型把内部标记的引号写错，浏览器把它拆成一串零碎属性），或者新生成的这一面标题和别的面一模一样，合并检查就整份拒绝。现在：
  - 依次拿页面上正在显示的版本、已保存的版本、重说前的版本做底，哪一份能干净合并就用哪一份，其他面一个字不动。
  - 新的这一面标题和别的面完全一样时，在标题末尾补上「（第 N 面）」再合并（多面镜要靠标题区分每一面，存档和翻版都用到）。
  - 真合并不了时，提示里会写明是哪一步没过，方便查。
- 失败的那一面不再只写一串内部代码（比如「原因：serial-face-failed」），改成说明文字。旧版本生成时就失败的面，当时没有记下具体原因，会写「这一面当时没有生成完成（生成它的旧版本没有记下具体原因）」；以后遇到没归类的错误，会带上内部错误代码。

## 1.67.62 按钮改容器属性值的写法能接上，内置生图不再重复发、不再跑题

- 反向接力认得另一种常见写法：一排按钮，样式里写的是“容器带某个属性值时显示对应内容、高亮对应按钮”（比如 `.sheet[data-scale="2"] .stage-2`、`.sheet[data-scale="2"] .tier-2`），却没有东西去改这个属性。点维修兔「修交互」后，这排按钮改由插件接管：点哪个就把容器的属性改成对应的值，内容和高亮都按模型自己写的样式切换。以前这种按钮会被当成“没写结果”，只加一个“已记录”的提示。按钮所在的大容器里另有插件区域（比如盖章）时也能接，两边各管各的。
- 内置生图：
  - 没开生图 LLM 时，同一段画面描述既当提示词又当自然语言描述发出去，柏宝绘里就出现两遍。现在两者相同时只发一份。
  - 开了生图 LLM 时，图框里写好的画面以前和整面文字混在一起发给它，同一段话出现两次，生图 LLM 还可能从正文别的段落或角色卡里另挑一幕、换掉衣着（比如问卷里提到一句“车厢”，就画成了古风车厢和汉服）。现在图框里的画面和出场人物的外貌、当时衣着单独发，并写明：只画这一幕，地点、时代、动作和衣着以这里为准；角色库、角色卡只补没写到的发色、眼睛这类稳定外貌，不覆盖当时衣着。

## 1.67.61 反向接力：老修复器修不好的手写区域改由插件接管

- 反向接力：模型手写的区域（没用插件写法），老修复器修完仍有点了没反应的按钮，而本面样式里写了这些部件的状态类（如 `.card.flipped`、`.tab.active`、`.panel.show`）却没有任何东西去加它时，改由插件接管：
  - 一排同款按钮配上同样多块写了状态类的面板，认成「多选一」：点哪个按钮就显示对应那块，选中的按钮和面板加上样式里写好的选中类；模型原本写死在第一个按钮、第一块面板上的选中类会拿掉，改由插件按当前选中项加，不会两个按钮同时亮。
  - 按钮自己、它的外层，或紧跟在它后面的部件写了状态类，认成「翻面／开关」：点按钮就加上或撤掉那个类（翻面、展开、点亮之类，样子都是模型自己写的）。
  - 只认样式里确实写了的状态类，不补内容、不猜目标；含勾选框、单选、滑杆、内层折叠的区域不碰，那些仍归老修复器。
  - 和正向接力一样只在点维修兔「修交互」或「全面维修」时做：先在看不见的副本里改好再点一遍，没反应的变少、原来能用的仍能用，才在真实页面照做；接管过的块记在本机，之后打开直接接好。巡逻结论会写「N 块老修复器修不好的手写区域已改由插件接管」。
- 更新日志按版本分开：README 每个版本一个小标题，插件里的「更新日志」只显示比你当前版本新的那几版，不再把所有版本的说明混在一起。

## 1.67.60 插件修复和老修复器打通（接力）

- 插件修复和老修复器打通（接力）：同一块区域同一时间仍只归一边管，避免两边一起改、互相抵消；但插件写法的区域修不好时，可以整块交给老修复器再试一次。
  - 点维修兔「修交互」或「全面维修」时，先在看不见的副本里把插件区域的控件逐个点一遍；有点了没反应的，就在另一份副本里把这一块“退还”（撤掉插件接线，模型写的标识原样留着），让老修复器整套去修，再点一遍。
  - 只有退还后原来能用的仍然能用、没反应的变少了，才在真实页面上照做；只是多了老修复器的“已点击”提示、实际内容没变化的，不算修好。否则保持插件接线不动，真实页面一点不碰。
  - 交接过的块会记在本机：之后重新打开、刷新、翻回这一面，接插件之前就直接交给老修复器，不用再点一次维修。巡逻结论会写「N 块插件写法修不好的区域已交给老修复器接手」。
  - 只在维修时做，打开兔子镜时不额外跑测试，不影响打开速度。用 92 面老成品回归，巡逻、修交互的结果和上一版一致。

## 1.67.59 写法跟着用法走，展现形式的交互细化

- 写法跟着用法走：每面先抽「真实用法」，再按用法里的动作配插件写法——“翻聊天记录”配翻页，“长按消息”配按住预览，“抽牌”配随机抽取，“翻牌”配翻面，“拧旋钮调频”配旋转拨盘，“对照号码”配连线，“刮开”配局部揭示……一千多条用法里约六成能直接认出对应写法。配上了的那条写法后面会注明「用于「某用法」」，并要求至少一种交互用这里的写法；用法里一条都认不出时，写法仍是随机提供、可不用。剩下的位置优先挑这个媒介里常用到的写法，不再完全随机（聊天面不会再随机到掷骰子）。滑杆／拖动一族仍只占一个位置，近期翻面、切页多时也照旧避开。
- 展现形式的交互细化：以前有一半的展现形式（147 种，如雾面玻璃、光栅卡、签语饼、存档与读档、黄历、求助 AI、To-Do List、亲友观察团、俳句、片尾字幕……）只能用所属大类的通用用法，“雾面玻璃”拿到的是“画画”类的用法。现在这 147 种每种都写了 5 条它自己的真实操作（雾面玻璃：用手指划过玻璃、擦开一块雾、哈气让它重新起雾、按住看轮廓、在雾上写字），抽用法时先从这里取 2 条，再从大类里取 1 条。用法池本身不进提示，提示长度不变。

## 1.67.58 七种新插件写法，维修兔按类修插件写法

- 插件写法新增七大类，每类都是不同的操作方式（不是弹窗换个名字）：
  - 翻面／开关切换：点开关（或点整张卡）翻到背面、亮灯、开盖，再点切回。
  - 分支选择／整幕切换：几个选项选一个，对应的那一幕出现，其余收起；可以设初始选中项。
  - 翻页阅读：一页一页往下翻，只显示当前页，手机上左右划也能翻；翻到头按钮不会变灰看不清，只是不再往前翻。
  - 随机抽取：抽签、掷骰、抽卡，每次随机落到一个结果，不连着抽到同一个。
  - 配对连线：先后点两端，连对了画上线并留着，连错有提示，全部连完出结果。
  - 旋转拨盘：转钮可以拖着转，也可以点一下转一格；可以按格停，转到指定格时出结果（保险箱、罗盘、收音机调频之类）。
  - 顺序解锁：按正确顺序点几个键（密码、旋律、咒语），按错重来，按对解锁。
  - 原来就有、但一直没提供给模型的「输入口令」也放进了写法清单。
  - 每面仍只随机给 3 种写法，提示长度基本不变；近期翻面、展开、切页用得多时，这一轮先不给翻面、多选一、翻页这三种。
- 所有插件写法共用一套显隐写法：容器里写 `data-rm-show="键"` 的内容，只在对应状态时显示（翻开时、选中那一项时、当前页、按住时、按对了、全部连上…），`"!键"` 反过来。按住预览、累积点亮这些老写法也能用。
- 维修兔按「类」修插件写法，不再一条写法一个补丁（跟随正文和独立 API 走的是同一条修复链，副本实测里也一样）：
  - 类型名写成别名或漏了前缀（flip、tabs、carousel、dial、lock、random、`data-ui=` 之类，中文也认）：换成对应的标准写法。
  - 声明的类型和里面的部件对不上（写的是翻面，里面放的却是选项和对应内容）：按部件认出真正的类型。
  - 容器只包住了画面、按钮写在容器外面：把容器扩到同时包住两者的最近一层。
  - 写了部件却忘了写容器：在部件所在的最近一层补上容器。
  - 部件写在 div、span、图形上而不是按钮上：照样能点、能用键盘操作。
  - 模型的样式写成 `.card.flipped`、`.tab.active`、`.panel.show` 这种类名：状态变化时把对应的类同步加上、撤掉（只撤自己加的）。本面样式对某个状态完全没写反馈时，给被点的部件加一圈当前文字颜色的描边，不至于“点了没反应”。
  - 这些都只在本面局部里补标识，不加内容、不猜目标；含有勾选框、滑杆、内层折叠的区域不碰，它们有各自的修复。修过的，巡逻结论会写「其中 N 处写错的插件写法已按类补齐」。
- 维修兔实测：已经选中的那一项、翻到头的翻页键不再算“点了没反应”；画面快照多看了转动角度和描边，转盘和连线的变化能看到。
- 只用插件写法、没有勾选框的一面，不再被记成「缺少有效内部交互」。

## 1.67.57 及更早的变动

- 修复「滑杆拖了没反应」的一类写法：模型写了一根滑杆（如“拖动调整显影分层”），画面上也盖了一层半透明叠加层，却没把两者连起来。现在本面没接线的滑杆，附近同一张卡片里只有这一根滑杆、并且恰好只有一层“铺满画面、不挡点击、没有文字”的叠加层（名字像 layer、overlay、lens、tint、滤镜、显影之类）时，拖滑杆就调这层的浓淡：最左完全看不见，最右完全显出来。不写任何内容；找不到唯一的叠加层就不接。叠加层本身画得很淡时，变化也会很淡，这种情况用「↻ 重说」更好。
- 出题规则补一句（26 字）：「滑杆只用下面提供的插件写法，自己写的拖了没反应，不要画。」这一轮没提供滑杆写法时就不画滑杆。
- 维修兔实测「按住」类按钮时，先按下、看完画面再松开（以前是按下又松开以后才看，画面早已复原，修好的按住也会被报成“没反应”）。按住时画面真的不变的，照样会报出来。
- 每面兔子镜至少两种不同的交互：以前提示里只要求“至少走两步”（同一种交互连着操作两步），所以常出现一面只有一个“按住”或一个“翻面”。现在交互构造、整体设计候选和短锁里都写明：每面至少两种不同的交互（如按住＋切换、刮开＋翻页、拖动＋点亮），第二种也要真实改变画面或内容，不能只是装饰或重复同一种操作；整体设计候选里每条方案也按两种交互来构思。只对 HTML 面，长文本不受影响。
- 修复「按住展开」类兔子镜按住完全没反应：插件的“按住”写法在按住时只给外层容器加 `data-rm-active="true"`，模型常照着说明把样式写在按钮上（`button[data-rm-hold][data-rm-active="true"] ~ …`），两边对不上。现在按住时容器和按下的那个按钮都带这个标记，松手一起撤掉，两种写法都生效；提示里的写法说明也改清楚了。
- 「近期记录」去掉重复：格式和以前一样（主题 × 形式｜骨架｜交互｜主色），五轮都写颜色，色号和色系都写，只是不再重复——色系名去掉括号里那串举例（“暖浅中性色（米白／米黄／奶油／燕麦）”只写“暖浅中性色”）；内容底色只写和主色不同的色号，色系也只写主色里没出现过的；“近白”只标一次。同样五轮记录（两轮三面）从约 1400 字降到约 1100 字，内容一项没少。
- 逐面抽取：勾了常驻、但「其余内容怎么抽」开着「随机抽取」又没勾范围时，报错会直接说明：可能是开了随机追加但「选择范围」里没勾任何分类或条目，并告诉你怎么改（只想用常驻就把「抽取方式」改成「不追加」；想再随机加几项就勾范围或改成「全部可用条目」，改完点「保存本面」）。范围里勾的正好是常驻那项、在黑名单里、或外置库条目找不到时，也分别写明。这种情况仍和以前一样不发送请求。设置页里也会当场提示，不用等生成才发现。
- 安全阀不再把写完的正文误判成“截断”：
  - 思考里或正文里提到“<content>”这几个字（比如“接下来输出<content>标签包裹的正文”），以前每提一次都多算一个没闭合的 <content>，正文明明写完了也会被拦。现在以最后一个 </content> 为准。
  - 正文写到 </content> 之后，后面的状态栏、小总结写得不规范（details 拼错、代码块收尾和标签写在同一行、状态栏没写完）不再拦兔子镜：正文已经完整，只检查到 </content> 为止。
  - 正文里的“a<b”“比了个 <w 手势”、随手写的 <code>、单个反引号，不再把后面的 </content> 吞掉。
  - 真的截断（<content> 开了没收、断在标签中间、正文里的代码块没收尾）照样拦。
- 「正文标签过滤」和提前生成：
  - 过滤只决定“发给兔子镜的内容里不带这些标签”，本身不会让兔子镜提前开始；要在正文写完、状态栏还在输出时就开始，需要打开「正文标签闭合后提前生成」并填正文标签（如 content）。设置页里补了这句说明，并改正了原来写反的“上面／下面”。
  - 开了提前生成时，正文外面的过滤标签（思考、状态栏、小总结）整段跳过：正文闭合后状态栏写得乱、还没写完，或者思考里提到了 <content>，都不再挡住提前生成。
  - 过滤标签的上限从 32 个提高到 128 个（32 是早年随手定的数，没有技术原因），扫描标签的上限也一起提到 128。
- 逐面生成某一面失败时写清真实原因，不再只显示「serial-face-failed」：比如副 API 拒绝了这一面（HTTP 4xx，常见于中转站内容过滤）、限流、服务端出错、模型拒写、没返回文字、输出被截断、结构没写完、网络中断、发送前检查没通过等；失败的那一面带「重说」按钮。
  - 撤回 1.67.46 的一处改动：那一版把 HTTP 400／404／422 当成“整轮都停”，只要有一面被中转站内容过滤拦了，后面的面全部标成失败。现在已经有面成功时只算这一面失败，后面的面照常生成；一面都还没成功时才整轮停下。
  - 发送前检查没通过（比如这一面超出请求预算）的面，不再反复排进自动重试，占掉别的面的重试次数。
- 短锁里的内置生图说明压短约 170 字，要求不变（人数男女、人物为主体、画面不出现文字、外貌照角色卡／Persona 原文）。
- 收藏星标：
  - 修复收藏后退出再进来星星不亮：有交互的兔子镜每次打开，插件会给里面的开关重新编一次号，收藏编号以前按整段 HTML 算，重进后就对不上，星星不亮，再点又存了一份。现在按这一面写了什么（标题和全部文字，包括没展开的部分）来认，点过哪个开关、展开到哪、手机上加的 ＋／－ 都不影响；以前收藏的也认得出来。
  - 已经收藏过的不会再收一次：星是空的时候点，如果收藏夹里已经有内容相同的一面，就不再存，直接亮星并提示「已经在收藏夹里了」。星亮着时点是取消收藏，内容相同的几份一起取消。
  - 收藏夹里新增「去掉重复」：只有真有内容完全相同的几份时才出现，要再点一次确认；每组留最早收的那一份，图鉴里关联到被删那份的，自动改成关联留下的那份。
- 内置小剧场生图更贴人设（没开生图 LLM 时）：
  - 你在柏宝绘角色库或智绘姬角色预设里配好的人物外貌，以前只有开了生图 LLM 才会用上；现在不开也会按原名对上，放在兔子镜模型写的外貌前面一起发出去（两边都留，不互相覆盖）。画面里点到了角色或 Persona 的名字、模型却漏写外貌时，也从角色库补上这个人。
  - 独立 API 下角色卡、Persona 只给模型前 2200 字，很多卡的外貌写在后面被截掉了，模型只能“未知不编”。开了内置生图时，会把截掉部分里讲外貌的原句（发色、瞳色、身高、痣疤之类）捡回来单独给模型，最多 600 字，不补别的内容。
  - 写画面提示时要求写清几个人、各是男是女（标签写法写 1girl、1boy），有人物时人物是画面主体；画面里不出现文字、字幕、界面和水印。外貌按角色卡／Persona 原文写明的转写，不改不漏。
- 上一版体检改动的复查（又查了一遍 1.67.46、1.67.47 改过的地方）：
  - 没有 name 的一排单选按钮：上一版改成“各自一组”后，模型写成标签页的那种可以同时选中好几个。现在只把同一排的几个当成一组（只选一个），整面其他单选不受影响。
  - 直接点 label 里看得见的勾选框：浏览器已经翻好了，插件不再翻回去再纠正，也不重复发变化事件。
  - 同一行里放了两根滑杆时，手机上的两条 ＋／－ 各认各的，重新打开不会多出按钮条，电脑上打开也接得上。
  - 撤回上一版的两处改动：逐面中间结果不再按 30 天自动清理（只有真的存满了才腾地方，重试补齐的那种最后才动）；本机存储额度不足时只缩本机快照，内存里的版本栈保持完整，不会让这一面再重说时从 1/1 起栈、把存档里的旧版本盖掉。
  - 撤回上一版的另一处：本机删了楼层但酒馆没来得及保存时，重新打开会照旧改用聊天文件里的版本（上一版错把这种情况当成“本机才是对的”）。
  - 维修兔实测：副本里先去掉“已修过”的标记、清掉旧的内联样式再接修复，不会把修好的控件报成没反应；只是鼠标变手形的元素没变化时不再算“没反应”（可能只是悬停效果）。
  - 逐面连发被远端拒绝（密钥、模型、参数错误）停下时，诊断里写成「密钥或权限被拒绝」或「请求参数被拒绝」，不再写成「发送前检查未通过」。
- 体检剩下的几条也补上了（上一版说“后面再做”的那批，还剩一条见末尾）：
  - 打开一面时快了：同一条消息的原文以前会被十来个修复器各自重新解析一遍（同一个字符串），现在只解析一次、大家共用；消息被编辑或换 swipe 后自然重算。消息正文指纹（挂载、头像绑定、逐面重掷都要算）也按消息记住，没变就不重算。
  - 原文体积预检不再把 `style="…"` 里以空格分开的每个词都数成一个属性（以前多算了三到五倍，样式很长的面会被误判“超出范围”，所有依赖原文的修复就都悄悄不干活了）；内嵌图片数据的扫描从逐字符改成一次查找，一张 150 KB 的图从几十毫秒降到忽略不计。
  - 手机上的 ＋／－ 按钮条不再硬塞在滑杆正后面：如果塞进去会改变本面样式里 `#r + .val`、`:nth-child`、`:last-child` 这类结构选择器的命中，或者挤进固定列数的网格／横向排列的一行，就往外一层放（最多四层）；放不下就不加这组按钮。往外放过的按钮条带着滑杆序号，重新打开时认得回来，同一行两根滑杆也不会认错。保存再打开后标记丢了只剩无障碍标签的旧按钮条也能认回，不再多出一条。
  - 点标题旁星标收藏／取消收藏：清理一次、算一次编号，查有没有和写入／删除放在同一个事务里，变动后只读一遍收藏夹给续篇候选和设置页列表共用；以前要开四次库、读三次、把这面 HTML 解析三次。
  - 本机 IndexedDB 里的版本存档（每面镜子的「重说」各版）以前只增不减，聊天删了、改名了那些行都留着。现在每次写成功后顺手把「不是当前聊天、而且半年没写过（或超出最近 60 个聊天之外）」的聊天整段删掉，一次范围删除，不读内容；当前聊天永远不删。聊天文件里每面镜子本来就带着自己的版本，删的只是本机这份副本。
  - 版本存档里的旧「已删除」标记不再无条件写回聊天文件：以前楼层搬家没成功时留下的一行可能属于别的消息，重新打开会把无辜的那一面判成“已被明确删除”。现在只有标记上记着的正文指纹和当前正文一致才写回；今后写标记时一并记下指纹。
  - 还剩一条没动：抽题里勾选的世界书条目会把正文前 1800 字存进设置文件。它在生成时要用，改成生成时再读世界书会多一次请求、读失败那面就没有这段，权衡下来先留着。
- 维修兔从「一种写法一个补丁」改成「通用实测」：巡逻时在一份看不见、碰不到的隔离副本里，把这一面每个看得见的控件都操作一遍——点按钮和标签、把滑杆拖到头、开合折叠——比较操作前后的画面；有控件操作后画面一点没变，结论就不再写「未发现异常」，而是列出这些控件的名字，并提示可以「↻ 重说」或把这一面发给作者。真实页面上的控件一个不碰，用户正在看的状态不会被动。副本里会重新接上和真实页面一样的全部修复，所以修好的控件在副本里也能动，不会把已经修好的报成坏的。副本里也会接回「轻触返回上一面」和「点主体翻面」这两种以前克隆后会掉线的开关。本面自己写了 pointer-events:none 的纯装饰不算控件；外层只是鼠标变手形、真正能点的是里面的按钮时，只算里面那个。健康结论末尾会多一句「实测：副本里操作了 N 个控件，画面都有变化」。用 85 面实际生成过的兔子镜验证：实测认定没反应的，和在真实页面上逐个点出来的结果一致。
- 全插件代码体检一轮（五路并行查，三十多条发现，这次修了其中的二十多条；剩下的几条是性能和存储上限类，后面再做）：
  - 画面：label 里直接放着可见的勾选框时，点勾选框本身以前会被我们的兜底拦住、勾不上，现在点框和点文字都能切换，再点一次能切回；没有分组名的一排单选不再被当成同一组互相顶掉；滑杆被模型写成禁用又带进度样式时，刷新或翻 swipe 后仍能放开，不会把位置重置回第一格；图框、样式里 `$&`、`$1` 这样的字符不再被当成替换符号吃掉；标签间只有换行时不再残留多余空白。
  - 导出与分享：下载本面 HTML 的链接改成新开页签打开；带大图的面导出见上一条。
  - 手机端：手机控制条只在手机上装，桌面端只复用已有的；步进很细（比如 0.01）的滑杆，手机上 ＋／－ 一次走二十分之一，不用点两百下。
  - 自动续写长文本：以前请求缺少正文和短锁段，被安全守卫拒掉后会一直显示“续写中”，现在按正常请求格式发，并在失败时明确报出来。
  - 多面兔子镜「逐面自动重掷」挂到正确的面上，不再把第一面当成所有面；每面的归属键带上这条消息的来源指纹，换了消息不会错位。
  - 选图鉴／抽题失败时，已经塞进提示里的那段兔子镜规则会立刻撤掉并弹出提示，不会带着半截规则把普通回复发出去。
  - 本机存储：输出、历史、swipe 版本、逐面结果的几处上限统计改成边写边算，不再每次整份重算；逐面中间结果超过上限时按 30 天、先旧后新、先别的聊天再本聊天的顺序清理；跨设备的归属纪元只在本机落后时才回滚，不会把更新的本机记录覆盖掉。
  - 多面连发里的失败判定：中止、配额、鉴权、400/401/403/404/422 这类错误立刻停下整轮；其余本地预检只在还没有任何一面成功时才算致命。
  - 其它：自动重掷次数上限 10；聊天头像提示里人设切换的回退；收藏剧场标题缓存、搜索防抖、缩略图观察器在关闭时释放；反馈猫、更新菜单、触屏剧场的几处监听泄漏；抽题条目预览只存前 1800 字；`:has()` 选择器在旧浏览器上报错时改用手动查找。
- 出题规则整体梳理了一遍，一件事只在一处说，「展现形式落地」仍然排在所有规则最前面，内容不变：

  - 固定规则大约少了五六百字；美化和交互的要求一条没减，只是不再重复。
- 外置库加了「编号 + 标题」的轻量索引，和内置库一样：列目录、选范围只读索引，抽中以后才去读那一条的正文。逐面抽取面板、收藏图鉴草稿打开外置库目录时不再一页一页从头读整库，几千条的库也很快，也不会再因为条目超过两万多条报错。旧库的索引还没有标题时，会顺序读一遍补出目录（只读一遍，不留正文）；重新导入或重建索引后就直接用索引。
- 收藏图鉴「按名称生成草稿」只发简短编号和标题（主题 t1、t2…，展现形式 f1、f2…），不再发外置条目那串很长的内部编号；目录太大时优先发和图鉴名称相关的条目，请求不会超长。
- 逐面抽取：保存的搭配可以删除了（「删除这套搭配」，要再点一次确认）；删除只删搭配本身，已经套用到各面的规则不受影响。
- 逐面抽取去掉「顺序轮播」，只留「随机抽取」，范围仍是你设定的范围。以前设成顺序轮播的，自动按随机抽取处理；本机留着的轮播进度也一并清掉。
- 修复「按 1 亮 2、按 2 亮 3、按 3 亮 1」：模型常把一排按钮写成“提示下一步”——选中第 1 项时去点亮第 2 个按钮，于是按下去的那个不亮、旁边的亮了，看起来像点错或没反应（其实下面的内容已经换了）。现在一组按钮里每一项都恰好去点亮另一项时，高亮改回按下的那个按钮自己；颜色和内容不变。提示里也补了一句：选中高亮落在按下的那个按钮上。
- 带图的兔子镜也能复制、下载本面 HTML：内置生图／插图画进图框后是一整张图片数据，以前一面里有这样一张大图就会被判成“超出安全导出范围”，复制和下载都被拒绝。现在导出时图片先单独拿出来，其余部分照常做安全检查，通过后再把原图放回去，导出的文件里图片完整。
- 自动生成的安全阀不再误判：正文里用 `~~~ 第二天 ~~~`、`~~~~~~` 当分隔线，或者某个标签里少写了一个引号时，以前会被当成“正文没写完、疑似截断”，自动模式下这条回复就不出兔子镜。现在波浪线分隔线按普通文字处理；标签少引号时只要后面还有 `>` 就照常往下看，真的断在半截标签里才算截断。
- 逐面生成多面兔子镜时，某一面在本地预检没通过（比如只有这一面超出请求长度），前面已经有面成功的话只跳过这一面，后面的面照常生成；只有本轮消息或生成归属变了才整轮停下。
- 人设列表翻页、筛选时，不再被当成“换了人设”而中止生图和重试；内置生图被中止时图框里留一个「重新生图」，不会一直停在“绘制中…”。
- 收藏图鉴：编辑格子时改了格子名称，原来手动关联的收藏不再丢失；一边生成草稿一边点别处的保存，编辑区的按钮不会再一直灰着点不了。
- 逐面抽取：把某一类切到「不追加」后，隐藏起来的数量框里的错误不再挡住「保存本面」；同名搭配保存时直接覆盖，连点两下不会多出一份。
- 修复「滑杆是摆设、内容一打开就全部摆出来」的兔子镜：模型有时写一根点不动的滑杆（停在最右边），下面一排章节、条目全部已经显示，说是拖动推进，其实什么也操作不了。现在滑杆格数和条目数正好相等、条目是同一种写法时，会把滑杆放开、从第一格开始：一打开只显示第一条，往右拖（或点 ＋）一条条显示出来，拖回去就收起。不写任何新内容。同时在整体设计说明里补了一句：控件不写成点不动的摆设，要靠操作才出现的内容不要一开始就全部摆出。
